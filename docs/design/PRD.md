# worldline 产品需求文档（PRD）

**版本：0.2 / 待评审（0.2修订：M1矢量画布与基础线面，地图自有坐标系）**\
**日期：2026-09-19**\
**代码基线：`dcb6479873f86b08354ba92b098dc260aa976624`（工具0.2.0）**\
**产品定位：世界内容、明确关联及展示文档的语言与工程核心。**

本PRD与[架构文档](ARCHITECTURE.md)、[共同契约](../../spec/presentation.md)、[65项需求清单](shared/REQUIREMENTS.md)共同使用。新增语法、命令和结构均未实现；引用R/E编号见[研究记录](shared/RESEARCH.md)。

## 1. 背景与问题

worldline已经具有解析、分析、世界/人物资料、标签、素材、别名、正文链接、时间关系、状态及叙事锚点；现有运行时负责故事选择和演练。[R13–R16]

用户的新目标不是增加一个模拟器，而是让作者共同编写的世界内容能够通过地图、百科、关系网络与故事视图读写。当前主要缺口是：地图配置没有统一生命周期；跨类型关系缺少独立身份；许多世界内容依赖自由tag约定；纯内容工程与可运行故事的有效性仍有耦合。[R04–R06]

必须先解决可保存、可校验、可引用的内容工程，再逐步拓展领域模板。不能要求作者先定义游戏规则、运行事件或配置变量才有资格使用地图。

## 2. 用户与使用场景

| 使用者 | 任务 | 当前需要改善的体验 |
|---|---|---|
| 世界作者 | 编写地点、组织、文化、人物和历史 | 只写一段正文也能建立条目；不必伪造可执行事件 |
| 共同作者 | 修改自己负责的内容，理解明确引用影响 | 同名不混淆、改名不断链、删除前知道哪里引用了它 |
| 编辑器开发者 | 从同一核心获取内容和展示索引 | 不在UI再解析一遍文本，也不维护重复设定 |
| 使用CLI的作者/维护者 | 检查工程、验证引用、提交修改 | 能检查地图元数据，区分语言错误与显示问题 |

角色是使用情境，不代表本期新增账号、权限系统或云端服务。协作以现有文件/Git加结构化讨论与修订为基础。

## 3. 产品目标与非目标

### 3.1 目标

- 支持只有世界内容、没有可运行故事的完整工程。
- 为多种内容和所有视图提供稳定身份及统一查询。
- 将共享地图、图层、标记和关系视图配置纳入保存、撤销、冲突保护与工程交换。
- 支持作者明确建立的跨类型关系及出处、范围、反查。
- 保持旧语言与既有演练语义，渐进增加自由内容实体和可选模板。
- 让变更可解释、可评审，正文不因模板或展示操作丢失。

### 3.2 非目标

完全排除世界模拟、自主演化、自动推进、行动调度、资源结算、NPC决策、运行态地图。也不包含酒馆角色卡、提示词/上下文构建、外部平台适配、完整地形绘制软件、全知事实推理与自动创作决策。

已有`runtime`继续可用，不删除，但地图/关系浏览不调用其推进接口。不新建sim crate。网络自动布局、索引和图像缩放属于展示计算，不生成世界内容。

## 4. 核心使用流程

### A. 纯设定工程

作者建立world和几个资料条目，不定义event；核心成功读取内容、保存工程并打包给合作者；请求试玩时单独返回“没有可运行入口”。不得要求添加虚假的start事件绕过校验。对应WL-028。

### B. 一份资料，多处展示

地图A和地图B各有一个标记引用同一灯塔；作者改灯塔显示名，两处未覆盖的标签均读取新名；挪动其中一个标记只改它的展示坐标；删除该标记不删除资料及另一标记。对应WL-001、007、008、011。

### C. 明确的跨类型关系

作者建立“守灯会—维护→灯塔”；人物另有“任职于守灯会”。可查询连接路径和原说明，但核心不推断人物将怎样行动，也不创建反向重复记录。对应WL-013–016。

### D. 并行修改

两个副本分别调整标记，合并时按ID比较字段；同字段或删改冲突不自动覆盖。内容关系改动与地图排版分开展示。对应WL-005、023、024及Q-009。

## 5. 功能需求

### 5.1 对象、内容与模板

**需求：WL-001、017–019、021；优先级P1，统一引用为P0。**

保留现有对象kind和ID；新增通用entity以place、organization、item等类型描述非人物设定。自由正文优先，字段可增减，中文显示名与身份分离。地图没有坐标也能保存对象；内容不因缺少某模板栏目而被判错误。

内置16类可选创作模板，具体字段和提示见[内容模板目录](shared/CONTENT_TEMPLATES.md)。模板不保存实例正文，不执行脚本，不依据某些属性给人物自动决定行为。应用模板只添加作者同意的新栏目，不覆盖旧数据。

作者状态（草稿/讨论/确定/替代）与陈述性质（作者设定/文献记载/人物观点/传闻/备注）分开。来源说明可为自由文字，能定位的来源使用显式对象引用。对无法验证的来源允许记录，不假造证据。

### 5.2 地图文档和多视图引用

**需求：WL-002、007–012、029；M1基础点线面（矢量画布），M4展示预设与专题。**

世界语义存.wl；JSON存地图配置。地图坐标系属于地图文档自身；栅格图层以素材ID引用位图并声明地图空间放置矩形，更换图层不动已保存图元。图层和标记各有ID。标记可连接已有对象、子地图或仅说明文字；不重复储存对象简介作为另一真源。

核心验证格式、ID、坐标、图层、对象和栅格图层引用，提供“对象在哪些地图出现”的索引。坏图层素材/坏地图不得阻止其他内容读取；坏文档保留原字节供修复。

点线面是局部图形，不是地理事实。移动、隐藏、删除展示项都不能触发世界状态、事件或关系变化。私人镜头默认不入工程。

### 5.3 关系网络

**需求：WL-013–016、020、027。**

关系类型可扩展，方向明确，同端点可同时有任职、债务等不同关系。逆向显示只查询原边，不能自动使“信任”对称或传递。

支持跨内容kind，端点条件是可选约束，不靠名称猜测对象。关系有说明、来源、作者范围，查询返回来源与截断标记。历史/版本范围是作者分类，不是当前事实求值器。

旧人物关系继续读取，提升为新关系须预览和确认。首版不把临时兼容句柄当永久引用。语义关系删除与视图隐藏是两个动作。

### 5.4 编辑、保存、删除与撤销

**需求：WL-003–006、008–012、027。**

地图文档必须进入Project的dirty、refresh、restore、mark_saved和打包生命周期。一次明确操作一次撤销；跨内容及地图的ID重命名必须整批校验再应用。

保存前检查基线；中断返回具体文件状态，不能只因第一份文件成功就显示全部已保存。新增删除墓碑及恢复流程。无法证明跨文件原子性时明确报告可恢复事务，而非宣称数据库式原子提交。

删除对象前返回所有明确引用的影响计划。作者可取消、重新绑定或显式解除引用；不自动删相关章节、关系网和素材。删除地图不等于删除地图展示过的世界对象。

### 5.5 内容历史、叙事与作者范围

**需求：WL-020–022、025。**

世界历史事件可以是普通历史条目，不必是可执行event。通过关系连接地点、参与者、文献、叙述scene与anchor。保留既有故事线/选择/演练，不重构它们来承载所有世界知识。

版本/时期只限定作者编写的内容显示范围；不生成中间状态。活动源码配置是M4功能，无清单保持原递归行为。不能把普通“旧稿”文件夹视为自动排除。

### 5.6 协作与检查工具

**需求：WL-023–026。**

批注可以锚定对象、关系、地图标记和带文档基线的正文片段。片段移动或重写后匹配不可靠则标记失锚。提案记录基线、理由、差异及影响，采纳前再次校验，不假定Git没有文本冲突就没有内容冲突。

新增工作区检查、地图列表和关系查询CLI；不改变旧wl graph的控制流含义。现有agent无需为此增加编辑器远控。本期不要求构建云协作或账户服务。

## 6. 质量与可观察验收

| 类别 | 目标 | 证据形式 |
|---|---|---|
| 保真 | 旧样例正常；新增内容和未知JSON字段往返不丢 | 旧测试、快照和负例 |
| 无副作用 | 浏览共享文件字节零变更；地图编辑内容字节零变更 | 哈希前后对比与属性测试 |
| 引用 | 改名不断链，ID迁移全部明确引用可定位 | 测试数据及影响计划 |
| 故障隔离 | 单张地图损坏仍可读其他内容 | 损坏文件样例 |
| 保存可靠 | 模拟每个写入点失败都可检测、恢复或保留冲突稿 | 故障注入记录 |
| 性能 | 1,000对象/3,000关系的局部查询P95≤150ms | M0冻结机器，M2测量；不是现有成绩 |
| 兼容 | Windows与WASM使用同一格式和身份 | 双端往返测试 |

严格指标与流程见[测试计划](shared/TEST_PLAN.md)。所有阈值是建议验收目标；未测不得标记通过。

## 7. 分期与退出条件

**M0：** 固定基线、配对CI、格式及非目标评审完成。\
**M1：** 纯内容工程＋矢量画布地图（基础点线面）＋地图元数据生命周期＋引用反查＋无污染保存通过；不依赖新entity语法。\
**M2：** 通用entity、独立关系、局部查询和CLI通过，与worldedit关系视图联调。\
**M3：** 16类模板、来源/观点、长文保真和历史/叙事关系完整。\
**M4：** 显式作者范围、展示预设与专题、批注、提案和文件级协作增强通过。

每阶段先通过核心契约测试，再允许编辑器依赖新API。详见[实施计划](shared/IMPLEMENTATION.md)。

## 8. 风险与产品取舍

最大风险不是功能数量，而是把展示数据当作内容、让JSON绕开保存机制，以及在新类型加入时破坏旧解析/指纹。通过分域命令、显式语言版本和成对发布控制风险。

允许不确定、留白、非地理内容和不精确历史；系统只验证结构及作者明确约束，不替作者判定世界是否“现实合理”。完整内容模板不是必须填满的完成度打分器。

## 9. 完成定义

需求有实现、可复现测试、示例、规范与迁移说明；UI/CLI均读取同一核心结果；未实现项在清单中仍为待完成。程序包导出仅指已有作品工程保存/交换，不借机加入被用户排除的外部格式产品。
