# ADR-0005：检查点三侧文本投影的比较基底

- 状态：已决定
- 关联：ikzerok/worldedit#18（CAP-04D）

## 背景

恢复预览已经绑定当前 Project 内容基线、工作区与磁盘摘要、检查点摘要，并列出逐文件操作和对象影响，但原 v1 检查点只保存一个文件快照。该快照与当前正文可以可靠地做两侧比较，却没有保存能为三侧文本投影充当基底的内容。当前工作区保存基线也不足以代替它：创建检查点之后的保存会移动基线；v1 记录没有保存时的基线字节。把当前保存内容或所选检查点猜成共同祖先会误导作者。

## 决定

- 新建 v2 检查点在捕获正文的同时捕获每个受跟踪 `.wl` 文件当时的保存基线；明确没有保存基线的受跟踪路径记为缺失。未跟踪的 `.wl` 附件不声称拥有保存基线。该基线命名为 `base`，当前 Project 缓冲命名为 `current`，所选检查点正文命名为 `checkpoint`。
- `base` 是可复核的捕获时保存基线，不声称为版本图中的因果共同祖先。预览是只读比较，不执行合并、不推断冲突，也不改变显式恢复语义。
- 若基线内容和检查点正文相同，存储引用检查点负载以避免重复；只有基线不同才写入额外负载，额外字节计入既有检查点配额。保存基线、文件负载与摘要都由记录校验覆盖。
- v1 记录继续列举和恢复，但没有 `base`。它们提供 `base_available=false`，只能显示有界的 current/checkpoint 原文片段并标明未对齐；不得假装缺失基线等于空文件。
- `Project::preview_checkpoint_restore` 生成文件操作和文本投影，复用 collaboration 提案审阅中的段落对齐逻辑。对齐不确定或遇到无效 UTF-8 时回退三侧原文片段，不生成精确段落范围；无效字节以转义形式显示。差异数、每侧文本片段分别受 presentation.md §11 阈值约束。
- 文本投影随 `CheckpointRestorePlan` 一起返回。恢复前 core 从当前 Project 与记录重新生成完整计划并比较；任一基线、工作区、磁盘、记录摘要或投影变化都会拒绝过期计划，且发生在写入前。

## 后果

v2 会为不同于所选正文的已保存源码版本增加检查点负载；相同内容复用原负载。旧记录仍可恢复，但其文本比较不会获得三侧对齐。UI 必须显示 `base` 的捕获语义和不可用/不确定状态，不能称其为分支祖先或可自动合并差异。
