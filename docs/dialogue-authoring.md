# 正式对白创作

工具 0.34 在原有正文工作区中加入正式台词编辑。语言仍默认 1.9，最高支持既有
1.13；没有增加 DSL 语法，也不会因为打开表单自动升级作品。

## 正文、台词与保存

普通正文（Text）和正式台词（Say）使用同一源码文件、同一 WritingBuffer。
正式角色按 character ID 选择，即使两个角色显示名相同，也不会混为一个人。
普通正文中的“姓名：”仍只是文字，不会被自动识别为说话者。

编辑器默认保留原有正文直编，即使本章也有 Say。明确打开“逐句对白”，或选择
插入正式台词 / 续写下一句，才进入同稿的 Text 与 Say 逐句界面。普通旁白也可
选择“编辑此句”走完整预览与纳入流程。关闭逐句模式返回正文入口，未纳入字段
仍受保护；返回后继续处理，不能把切换模式当作应用、取消或保存。

编辑过程有三个不同状态：

1. 表单输入尚未纳入：保留在当前受保护表单中
2. 纳入正文草稿（stage）：只更新当前文件的唯一缓冲，工程与磁盘不变
3. 应用正文到工程：更新 Project 内存；点击保存后才进入原有可恢复磁盘保存事务

源码、连续正文和台词编辑是同稿的不同入口。预览、取消、无变化、失效计划及错误
不会部分提交。无效源码仍可在完整源码入口保留和修复，不能用上次正常投影冒充
当前稿。外部变化或其他修改导致计划过期时，保留输入、重新打开当前来源并预览。

## 字面文字、表达式与强链接

台词内容按 typed parts 编辑：

- literal：已经解码的普通文字，花括号或链接样式不会自行变成语法
- expression：明确新增或修改的表达式源码，不带最外层花括号，由 core 校验且不求值
- link：完整目标 kind/ID 和显示文字，由 core 生成并校验正式链接

引号、反斜杠、中文、emoji 和换行由 core 编码。Enter 只在当前句内加入换行；
明确“下一句”或 Ctrl/Cmd+Enter 才开始新语句，不自动轮换角色。输入法组合期间
不得触发提交、转换或跳转。下一句沿用角色只是可修改的表单默认值。

普通 Text 的既有语言表示能力较窄：不能无损编码的注释样文本、边缘空格或控制
字符会明确拒绝，不会被偷偷清洗或转为另一种语句。复杂原文可以继续在源码编辑。
只有 core 已证明精确来源范围的选区才可关联资料；解码后偏移不能冒充源码偏移。

## 旧稿启用台词

Say 属于既有语言 1.11。1.9/1.10 作品第一次采用正式台词时，必须明确选择预览
启用 1.11，并查看全稿诊断、关键词解释变化、运行指纹影响和清单改动。

确认后，语言清单、当前文件完整未应用稿和所选台词编辑作为同一个 Project
事务提交，并可一次撤销；这一步仍不保存。无法迁移的候选只提供诊断，不能提交。
已经高于 1.11 的作品保持当前语言，不降级。取消不会留下清单或半条台词。

## 转换、删除与本地化

转换只针对一条正式 AST Text/Say，不能拿合并显示段落、任意选区或多条句子代替。
带粘接（glue）或普通标签的 Text 不能无损转换为当前 Say，必须明确拒绝。

Say 转为 Text 时，正式 speaker 会移除。存在 direction 时，预览列出具体演出
备注，作者确认移除后必须重新生成计划；旧预览摘要不能加一个开关直接提交。
删除预览也会列出将移除的备注、本地化源 ID 或标签，行尾与独立注释仍保留。

更新和转换保留稳定 localization ID 及旧译文。Text↔Say 改变源单元种类，旧译文
会按既有规则变为 stale。只修改 speaker 或 direction 不改变当前翻译源 revision，
译文可能仍为 Translated；但角色归属和完整稿快照已经改变，旧角色台本必须重查。

## CLI 与 RPC

机器入口复用同一 core 投影、严格 typed 请求和预览摘要：

- CLI：`wl dialogue query|preview|apply PROJECT`
- RPC：`dialogue.query`、`dialogue.edit.preview`、`dialogue.edit.apply`

query 返回当前 Project 的正式 statement/anchor ID。构造 schema_version=1 的
DialogueEditRequest，填 expected_baseline、target、generation=0 和明确 operation，
先 preview，再以返回的 plan_digest apply。更改字段或确认选项后须重新 preview。
请求拒绝未知字段、重复键与超预算内容；不能通过机器输入绕过来源、草稿或只读
保护。query 的 ID 只对该完整当前快照有效，不是永久行身份。

每次机器调用只操作其自身打开的 Project；它不能遥控 GUI 的未应用草稿。
apply 默认只改内存，RPC 的 `project.save` 或 CLI 明确保存选项才写入磁盘。
未保存的短命 CLI 进程退出后不会留下编辑结果。语句详情与命令参数以
[机器接口规范](../spec/dialogue-machine.md) 为准。

精确字段、预算、受保护计划和来源映射规则见
[正式对白作者契约](../spec/dialogue-authoring.md)。生产台本查询与交付采用独立的
[制作台本契约](../spec/production-script.md)，不会复制另一套台词真源。

新建或修改的表达式受 256 个正式 token、64 层括号/一元嵌套预算保护，超限会保留
输入并拒绝应用。已经编译的未改复杂表达式不会因修改文字、角色或备注而被削减。
“下一句”由 core 按刚应用的精确结果重新确定来源与安全插入锚；文件、附件库存或
后续输入变化时需要重新选择，不会拿旧偏移接着写。
