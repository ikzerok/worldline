# 按真实分支边界审稿

0.22 的作者审稿保留同一份语言源码的静态结构。它回答“我写了什么，各段属于哪个条件或选择”，不回答“玩家这次一定会看到什么”。实际结果请在试玩或路线对照中检查。

用 worldedit 打开自己的作品，进入书稿工作台；本指南不依赖发行包内的演示工程。

## 命令行与机器接口

```sh
wl manuscript-review ./作品 --target-json '{"kind":"event","id":"dawn"}' --json
```

目标也可为 scene、fragment 或 entity。输出使用 core 的同一审稿 DTO：条件组与分支、相邻选择组、场景和流程说明有明确结构；台词提供人物显示名与完整身份；各真实语句带当前源文件和UTF-8范围。动态内容保留占位，调用只显示目标及参数而不展开或执行。

JSON-RPC 在已打开工程后使用 `manuscript.review`，参数为 `project_id` 与 `target`。读取当前已加载工程稿，不暗中刷新磁盘。CLI使用只读工程入口，不替作者恢复保存事务、应用输入或保存文件；正在运行的编辑器未应用草稿不在另一个CLI进程里。

## 读结果

1. 先确认 ok 和 complete。编译、目标、来源或预算失败没有可冒充全稿的部分成功
2. 条件、once和enable是静态约束，未求值。if/else分组与不同的独立if分别保留；结束组只表示源码结构结束，不保证跳转/return后的路径会汇合
3. 人物姓名方便阅读，稳定kind+ID用来分辨同名对象。正文标签保留作者指定文字，不把姓名更名偷换成所有散文替换
4. 定位必须用产生投影的完整源码与编译选项重新核验；注释移行也会使旧来源失效。不要只看运行指纹相同就继续用旧行号
5. 片段未展开不是空片段。单目标完整性不包含被调用内容、其他资料或实际输出

## 边界与交付

核心限制为参与编译源码16MiB、单投影10000节点、嵌套深度64、JSON结果1MiB；详见[正式规范](../spec/manuscript-review.md)。超限请按已编排章节分开审阅，不能把缺失章节当作没有正文。编辑器整书还受累计缓存预算限制。

作者审稿可看到作者自己的条件、身份和源路径，因此不是公开读者包。对外发布继续用已有 reader-export 的显式对象/章节/字段/附件选择；本功能不改变 v1/v2/v3 的公开内容、权限或文件格式。完整源码工程是可重开的备份，公开阅读包不是工程备份。
