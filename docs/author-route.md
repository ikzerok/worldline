# 从资料到可信重放

用[栖雪山站最小示例](../examples/snowline-seeds/README.md)完成一次资料整理、双路线写作和安全改稿。先复制示例到自己的作品目录。示例显式选择语言 1.13；产品 0.12 的修正不新增 DSL，旧工程仍按自己的语言版本打开，默认仍为 1.9。

## 先建资料 再写这一次的后果

在 `lore.wl` 中，人物、种袋和原簿各有一个稳定 ID。种袋的 custodian 是指向人物的 `ref("character", "botanist")`，正文里的 `[[entity:register|苗圃原簿]]` 是强链接；普通同名文字不是强引用。显示名称、别名和链接显示文字可与身份不同。

两条 recounts 关系分别保留原簿与站务的 `source_note`，都指向 collection，不复制事件，也不自动裁定哪份记述正确。改稿前查看目录、来源和使用位置：

```sh
wl catalog 我的作品 --json
wl relations 我的作品 --target event:collection --depth 1 --json
```

静态 property 用于资料。`knowledge`、`paperwork` 是单次故事的状态，`label_count` 是运行变量；它们只随实际走过的路线变化。不要把所有分支中的状态动作拼成一份已经发生的历史。

## 分开世界先后 展示顺序和实际阅读

示例用三个同根时段保留 collection、handover、delivery 的真实归属，显式 `follows` 写出 collection → handover → delivery。语言 1.13 允许同一明确时间根内跨直接时段；1.9–1.12 仍要求同一直接时段。

实际阅读先进入 handover，再跳到 collection 回忆，最后到 delivery。`->` 和 choice 控制执行，`at` 只排作者概览，书稿章节还可独立编排。调整 `during/follows` 不会替作者执行事件、重放效果或改阅读顺序。

```sh
wl timeline 我的作品 --json
wl graph 我的作品 --json
```

时间图是偏序：同层不表示同时，不同层也不自动证明任意两点有先后；需要查看明确连线。没有写下的日期、历法或因果不会被推导出来。

在配对编辑器里，改 handover 的所属时段后，仍合法的 collection 前驱继续保留；已选但不合法的关系会显示原因并阻止应用，不会被悄悄取消。作者可明确取消具体前驱，但后继事件仍可能约束它，应用前需要通过整个工程的校验。更多步骤见 worldedit 的“时间约束与可信重放”。

## 两条路线共用一个检查片段

world.wl 的两个选择分别 `call inspection("苗圃原簿")` 和 `call inspection("运输清单")`。片段在菜单处暂停；选完或 return 后回到各自调用后文。参数 document 和 local labels_before 属于这次调用，存读档会保留；片段内跨事件跃迁或 END 则清空返回链。

`may_label()` 每次读取当前知识和手续，结局不必复制条件。菜单的 `if` 隐藏不该出现的选项，`enable ... disabled ...` 保留可见但不可选的选项；说明不是调试条件值。示例的两条完整输入及最终状态见示例 README。

先分别演练两条路线，再记录轨迹。走过两路只证明这两路，不等于穷举所有组合。普通试玩超限是可恢复暂停，不是 END；可以调整预算继续，见[有界推进](../spec/bounded-execution.md)。

## 让重放比较剧情变化

`wl play --trace-output=...` 记录真实选择和观察，`wl replay --trace-json ...` 对照当前编译稿。重放按稳定选择 ID 找选项，不按旧菜单下标代选。编辑器“保存当前路径”只保留本次工作台会话；要长期留存，请导出路径 JSON 并另存文件。

在运行语义未变且相关格式兼容时，给共享片段加空行或注释、复制工程目录、合法移动文件并更新引用，都不应只因调用帧的源码位置改变而出现分歧。0.12 的比较仅排除调用帧顶层 file/line；原始轨迹、当前文件/行导航仍保留，参数、local、调用对象、栈顺序与执行位置、输出和真实状态仍比较。

请用同版工具生成和重放轨迹。ReplayTrace 与调试检查点严格匹配 runtime 版本，并校验各自 schema；0.11 生成的轨迹不能直接在 0.12 重放，本版不迁移或放宽此规则。“旧轨迹形状可读取”仅指 runtime/schema 已兼容时的旧可选 DTO 字段形状。

通过这些检查后，入口轨迹可在新运行指纹上受控重放，并在首次观察差异处停止；检查点起始轨迹还必须匹配程序 fingerprint。普通 Story 演练存档沿用独立的读取格式、必需能力及指纹规则，不等同于 ReplayTrace 的严格 runtime/schema 绑定。不能删除校验字段来“修复”不兼容。预算耗尽、取消、分歧与完整重放是不同结果。详见[重放契约](../spec/replay.md)。

编辑器的结果跳转只使用本次 ReplayResult 在当前程序中的真实位置；旧轨迹行号保留作预期对比，不是当前跳转地址。结果产生后又改了稿，须重新重放。若执行已经结束或目标缺失，且本次结果没有实际位置，就明确不可跳转，不猜活动文件或附近行。

## 应用和保存是两个步骤

1. 输入正文或表单值后，先看诊断和受影响引用。预览不会自动把草稿提交到工程。
2. 点当前工作台的“应用更改”或对应应用动作，通过基线和校验后更新工程缓冲，可撤销；此时可能仍未写磁盘。明确的完整源码草稿通道允许保留错误，结构表单不能因此跳过校验。
3. 用保存全部写入磁盘，再重开确认。未应用输入不因为按过保存就已提交；完整工程导出也会列出这部分输入，由作者决定返回处理、取消或仅导出已应用版。
4. 遇到过期草稿或外部修改，先保留现有输入，查看差异，再在最新基线上合并；不要反复用旧预览覆盖。取消不等于同意丢弃。

演练存档只保存故事状态；工程备份应保留完整目录。公开读者包采用另外的披露白名单，不能把包含来源笔记的完整工程当作无剧透发布物。

## 改名范围要先确认

| 要改的内容 | 当前支持与边界 |
|---|---|
| 显示名称、别名文字、正文称呼 | 与稳定 ID 分开；改显示名不会自动重写链接显示文字或普通同名正文 |
| entity、relation 的稳定 ID | 有逐处真实修改语境和整批重命名计划；仍须满足语言、基线、完整分析和可写条件。作为 state 所属对象时 ID 参与运行指纹，仍拒绝改名并解释受影响状态与旧存档原因 |
| rule、fragment、character、tag、state 的稳定 ID | 统一重命名要求显式语言 1.11 或更高；运行身份变化可能使原存档不兼容 |
| event、scene、file 的身份或文件路径 | 不在统一安全重命名白名单；本版没有一键跨文件安全改名承诺，CLI/RPC也没有通用同等命令 |

需要手动搬文件时，在工程副本中处理 include、相对路径及其他已知引用，再对完整工程检查和演练。仅有一次 check 成功不等于所有普通文字都已更新，也不等于多文件操作获得了原子重构保证。运行语义相同的合法文件移动可以重放通过，并不代表编辑器提供了安全文件改名功能。

0.13 的预览列出相对路径、具体行或字段、修改前后完整语境与运行指纹。源码只改真实身份 token，同行注释、引号显示名与链接显示词保持原字节。所有引用必须一起应用；取消、过期或磁盘外改时整批不变。被 state 引用的实体可保留 ID 改 `as "显示名"`；关系可保留 ID 改 `alias relation ID as "别名"`。本版不提供运行身份迁移，也不修改旧存档。
