# worldline 语义与执行模型

**版本:** 1.9
**前置:** `syntax.md`

本文定义 worldline 源文本的执行语义:运行时如何消费编译产物、
如何呈现文本与选择、状态由什么构成、存读档的边界。

---

## 1. 编译产物

`worldline-core` 将源文本(含 include 合并)编译为:

1. **Program**:事件/场景的有序集合,每个节点持有语句序列(AST);
2. **Analysis**:符号表、引用解析结果、诊断列表、关系图;
3. 诊断含 error 时,Program 仍产出(尽力而为),但运行时**必须拒绝执行**。

## 2. 执行模型

运行时(`worldline-runtime`)是一个确定性状态机:

```text
Story {
  program: Program          // 不可变
  state: StoryState         // 全部可变状态
}

StoryState {
  vars: Map<String, Value>       // let/const 变量
  visits: Map<NodeId, u32>       // 事件与场景各自的访问计数
  turns: u32                     // 已完成的选择回合数
  pointer: Option<FlowPoint>     // 执行游标;None = 已结束
  taken_once: Set<ChoiceId>      // once 选择已选记录
  rng: u64                      // 随机数生成器状态
  storyline: StorylineId         // 主角当前故事线(漂流/主线变动切换)
  states: Map<StateId, Vec<TagId>> // 当前标签集合，包含身份状态
  state_history: Vec<StateRecord> // 已执行状态操作及前后集合
  met: Set<CharacterId>          // 已登场人物
  anchors: Vec<AnchorRecord>     // 锚点记录(手动 + 各类变动,按发生序)
}
```

- **进入节点**(事件或场景)时 `visits[node] += 1`;当前不保存完整的节点回放轨迹。
- 进入事件时:若其首个子节点是场景 → 自动下潜进入第一个场景;
  否则从事件体语句开始。
- **FlowPoint** = (节点 id, 语句下标)。执行即从该点逐步推进。

## 3. 一步推进(tick)

运行时以 `tick()` 推进,直到产出文本或到达暂停点:

| 语句 | 行为 |
|---|---|
| 文本行 | 求值内插 → 追加到输出段;若带 `~` 与下一条文本输出粘接 |
| choice 组 | 汇总本组所有选择:过滤 `if` 假、`once` 已选 → **暂停**,呈现可选集;无可用选择则落穿到组后 |
| divert | `-> END` 置 `pointer=None`;否则进入目标节点(计数+下潜),游标置目标首语句 |
| if | 求值条件,进入匹配分支;无条件命中且无 else → 落到 if 组之后 |
| let/set | 求值并写 `vars`;set 到未声明符号为编译期错误,运行期不触发 |
| become with/add/remove | 替换/增加/移除状态标签，追加含操作类型与前后集合的状态历史 |
| meet/part | 立即变更 `met` 并写入演练锚点记录(§8) |
| 旧 grant/revoke | 编译时归一为叙事身份状态的 add/remove；兼容锚点记录由该状态动作派生 |
| anchor | 产生一条手动锚点记录(§8) |
| 嵌套块 | 深度优先执行;块结束落回父块下一条语句 |

## 4. 选择与汇聚

- 玩家选定选择 i → `turns += 1`;`once` 记入 `taken_once`;
  游标置该选择块首语句,继续 tick。
- 选择块执行完未跃迁 → 游标落到**整个选择组之后**的语句(隐式汇聚)。
- 内层组耗尽/执行完 → 落到内层组之后,即外层选择块的下一条语句。
- 不同分支可以汇合，也可显式跳回之前的节点。执行图允许环；A206 是循环风险提示。`follows` 时间图仍禁止环，两个图不相互推导。

## 5. 输出契约

`tick()` 循环产出 `Output` 流:

```text
Output ::= Text { content: String, new_line: bool, tags: Vec<String>, links: Vec<RenderedLink> } | Ended
```

- 文本行默认段落模型:连续文本行间以换行相连;
  `new_line=false` 表示粘接(上一行行尾 `~`),消费端不再插入换行。
- `tags` 为该行 `#标签` 元数据,不属正文,宿主可自行消费。
- `links` 保留显式对象链接：`{start, end, target: {kind, id}}`，start/end 是求值后 content 的 UTF-8 字节范围，左闭右开。文件目标解析为工作区源码路径。只附带阅读信息，不重新求值插值、不触发对象或改变存档；没有链接时 JSON 省略 links 字段。
- 选择呈现不是 Output——它是 Story 的暂停态 `choices()`,
  元素含:标签文本(内插后)、源码行、组内偏移，以及同规则的 links（范围相对 label）。
- `-> END` 或事件体执行完无跃迁(视同 END,编译期给 hint)→ `Ended`。

## 6. 确定性与随机

- `rnd(a,b)` 每次求值推进随机数生成器状态,该状态随运行存档保存与恢复。
  暂停选择组载入后会重新求值,因此包含随机表达式的选择组不保证显示同一结果。
  影响分支的随机判定可先 `set` 到变量再使用,避免重建选择时重新取值。

## 7. 存读档

v1.6:世界观、人物属性和关系是静态作者资料;不改变运行期状态。
这些资料发生内容变化时参与指纹校验;事件 `at` 序号仅为展示布局,不参与指纹。
`period` / `during` / `follows` 描述世界时间关系,不改变执行状态、不参与运行存档指纹。
`tag` / `asset` / `mark` / `attach` / `anchor_def` / `anchor_link` 是创作目录元数据,同样不参与运行存档指纹;正文原有 `#标签` 的输出契约不变。
未使用新元数据的旧故事保留原指纹策略,注释与文件移动不影响指纹。

`StoryState` 可全量序列化为 JSON(serde)。

- 存档兼容性:Program 内容变化(改稿)后旧档**不保证**可续玩;
  运行时校验程序指纹(内容哈希),不匹配时给出明确错误而非静默错乱。
- 暂停态(等待选择)**不入档**:载入后首次 `continue_story()` 会重新
  遇到选择组、按当前变量重新求值可用性与标签,并再次暂停——
  除 `rnd()` 外该过程确定,与存档前状态一致。
- 存档覆盖 `vars`、`visits`、`turns`、`taken_once`、帧栈、随机状态、`storyline`、`met`、`anchors`、`states`、`state_history`。保留的 `perms` 字段是从身份状态派生的兼容快照，不是独立可变状态。
- 多周目:新建 Story 或 restart 重置演练状态，状态集合恢复声明初值，历史清空。
- 权限迁移保存旧指纹与归一后指纹的精确对应，只有对应匹配才可把旧档权限注入世界叙事身份状态；拒绝未知权限、缺失状态及冲突来源。其余改稿仍按指纹不匹配拒绝，详见 [states.md](states.md)。

## 8. 故事线、准入、效果与锚点

### 8.1 当前故事线

- 新建故事时 `storyline` = 入口事件所属故事线;
- 漂流跃迁 `->>` 进入目标节点时,`storyline` 切换为目标事件
  所属故事线,并写入一条"漂流"锚点记录;
- 效果动作 `to <故事线>` 在效果生效时切换 `storyline`
  (不改执行流),写入一条"主线变动"锚点记录。

### 8.2 事件准入

进入事件（入口、`->`、`->>`，包括重新进入当前事件）前，`after` 必须求值为真；身份要求用 `has(状态, 标签)` 表达。旧事件 `perm P` 在编译时合并进 after，迁移兼容信息保留身份闸门先行的检查与缺失权限提示；读取的仍是同一个状态集合。作者改写或删除对应准入表达式后，不继续施加隐藏闸门。

准入失败是运行期错误而非静默跳过——作者可使用 `if` 守护跃迁。同事件内场景跳转不重新准入；跨事件进入场景仍需通过目标所属事件的准入。离开源事件时先执行源 exit 效果，再检查目标要求；失败保留已发生的效果，不重复执行。

### 8.3 效果执行时机

- `on enter`:准入通过后、事件正文之前;重入重发(幂等动作除外)。
- `on done`:事件根帧自然弹栈时(正文执行到末尾,无跃迁);
  `->`/`->>` 离开不触发。
- `on exit`:离开事件时执行一次；自然完成时先 done 后 exit，跃迁、END 和同事件重入均触发 exit，同事件内场景跳转不触发。
- 效果条件 `if` 为假时整块跳过(不产生记录)。
- 效果与内联 become 共用状态操作实现，追加 `state_history`；meet/part 更新人物并追加演练锚点；`to` 切换 `storyline` 并记录。旧 grant/revoke 先归一，兼容记录从身份状态动作派生。

### 8.4 锚点记录

```text
AnchorRecord {
  kind: Manual | Drift | Shift | Grant | Revoke | Meet | Part
  name: String        // 手动=声明名;自动=固定名(漂流/主线变动/权限授予…)
  note: Option<String>
  detail: Option<String>  // 自动记录的对象:目标节点/故事线/权限/角色
  node: Option<String>    // 发生时所在节点
  storyline: String       // 发生后的当前故事线
  turn: u32
}
```

记录只增不减,全量入存档;时间线视图与试玩检查器按序展示。

### 8.5 独立锚点与状态出处

`catalog.anchors` 保存独立 ID、名称、叙事意义及对象链接。它属于作者目录，不进入运行帧、不追加 `AnchorRecord`、不改变存档指纹。`Catalog::anchor_changes` 从状态分析索引借用关联状态与关联事件的共同动作；未执行的条件分支仍显示为源码出处，不能视作真实历史。详见 [catalog.md](catalog.md) §4。

## 9. 错误处理

- 编译期(诊断)拦截一切已知错误;运行期错误仅剩:
  目标准入拒绝、动态表达式错误、执行步数保护、无效存档及指纹不匹配等。运行失败通过 RunError 报告，已发生的效果不自动回滚。

## 10. 与 Ink 运行时的差异

- 无 call stack / 线程:worldline v1 只有线性游标,状态机可完整快照;
- visit 计数在"进入时"而非 Ink 的"进入后"结算,`visits()` 在本节点内
  求值至少为 1;
- JSON 存档是**状态快照**,不是 Ink 那种与编译产物耦合的 runtime JSON。

## v1.9 状态与身份统一

状态、has 查询、become 三种集合操作、旧权限迁移与存档指纹规则见 [states.md](states.md)。旧 done 和正文 anchor 行为保持不变。

正文对象链接见 [catalog.md](catalog.md) §5：正文和选择中的 `[[类型:ID|显示文字]]` 仅输出显示文字，邻接字面量按完整可见文字计算指纹。增删链接而保持相同文字、修改别名均不影响存档兼容；显示文字变化仍使指纹变化。对象其他既有字段的指纹规则保持原样。阅读链接不进入执行目标，也不修改人物在场或状态。
