# 工作区目录契约

工作区是用户选择的一个主目录，根目录 `world.wl` 是默认入口。桌面启动必须选择目录；新建也先选择目录。兼容命令行传入根目录中的 `.wl` 入口，此时其父目录就是边界。

工具0.29起，新建作品只生成 `world.wl` 的空白骨架：`event start` 后直接 `-> END`，不预填世界、人物、正文、地图、书稿或额外文件。内存新建仍为未保存状态，显式保存/导出后按普通工作区重开；该起点允许零正文试玩自然结束。既有作品不受此默认值变化影响。

目录内所有子目录递归遍历，按路径稳定排序。无显式源码配置的旧工程中，全部 `.wl` 文件加入工程缓冲、搜索和统一分析，不必靠 include 才能被发现。include 仍决定显式加载次序，同一文件只合并一次；默认入口事件优先取入口文件，再取 include 顺序，最后取其余文件路径顺序。其他类型文件保留在工作区文件清单中，不当作语言源码解析。使用子目录划分人物、章节、参考资料和附件；ID 在全工程唯一。

启用 required feature `workspace.source_sets.v1` 后，清单可提供 `source_config={mode:"explicit",active:[...],archived:[...]}`。Project 仍加载并保留工作区内全部 `.wl` 缓冲以便编辑、另存与归档，但编译、分析和机器查询只消费 `active`；工程入口必须属于 `active`。标为 `archived` 或其他未激活源码不会被偷偷载入，活动源码的 `include` 指向它们时报告 A105。路径必须是工作区内相对 `.wl`，active/archive 不得重叠；配置无效使用 WS005，并保持只读错误状态，不退回“全部递归”掩盖错误。没有 `source_config` 的旧工程行为不变。

路径必须留在工作区内。include 和附件采用声明文件所在目录的相对路径，允许 `../` 到工作区内的兄弟目录，禁止绝对引用和跨出根目录。链接与 Windows 目录联接不参与遍历；发现时报告错误，避免漏导出或跟随到外部。路径边界在读取与写入前检查，包含尚未创建文件的父目录解析。越界诊断为 A109。外部素材须先由用户复制进目录，再引用。

桌面约每秒检查文件变化。无本地修改的源码自动更新，新增源码加入、删除源码移除；有未保存修改的文件保留缓冲与旧保存基线，并提示冲突，保存不会静默覆盖外部内容。外部源码刷新清理旧撤销记录，防止撤销恢复过期磁盘内容。对象表单中尚未提交的输入保留；源码外部更新后阻止旧表单提交，需保留输入并关闭、重新打开表单再合并，避免覆盖刚刷新的内容。附件和其他文件变化也触发分析刷新。

导出和另存包含全部普通文件，包括未引用附件、说明、隐藏文件及 `.agent` 创作资料，保持相对路径与内容；源码采用当前缓冲。导出要求编译通过且声明的附件可读，另存允许未完成源码。目标必须是工作区以外的新目录，避免自我递归。用户的 README 和 spec 文件不被自动生成内容覆盖。空目录没有创作内容，文件型 ZIP 不保留空目录。

工具 0.24 明确修复完整工程打包遗漏已跟踪非活动源码的问题：完整导出与另存的源码
集合为全部非删除缓冲，包含 active、archived 和其它未活动稿的当前原始字节。
清单的 active/archive 成员及扩展字段保持原字节，重开仍只编译原活动集合；不会因
进入备份包而自动启用归档稿。墓碑、保存事务及本机检查点仍按既有规则排除，链接和
越界仍拒绝。此修复只补齐已跟踪源码，不扩大未知文件接管范围或读者公开授权。

面向读者的静态发布使用独立的显式选择清单，只包含选择中的对象、逐章授权的书稿内容和资产 ID；引用闭包、地图可见性与附件关系不会自动公开其他内容。作者预览中的排除清单不进入发布包。此发布边界不改变完整备份、另存工程或 ZIP 的全文件保留语义，详见 [reader-export.md](reader-export.md)。

外部 Markdown 资料只通过显式预览/应用迁入；支持子集、原文副本、附件、映射与损失报告见 [markdown-import.md](markdown-import.md)。导入应用遵守内容基线、目标路径缺失基线和可恢复保存事务。

浏览器工作区是用户授权导入的目录快照，遵守相同边界与递归分析。浏览器普通文件选择接口没有持续读取磁盘的权限，因此磁盘外部变化需要重新导入；保存/导出下载完整 ZIP。不得将快照宣称为实时磁盘同步。限制见编辑器说明。

## 创作文档会话

Project 将 `.wl` 源码与清单注册的展示 JSON 分别保存在源码文档与 `authoring_documents` 中。后者包括 `.world/project.json` 自身及其 `maps`、`graph_views`、`manuscripts`、`saved_queries`、`templates`、`localizations` 等注册项，保留原始字节；无效 JSON 和无效 UTF-8 不得在读取或另存时被替换。未注册 JSON 仍作为普通文件完整保留。无清单的旧工程打开时不自动创建清单；首次保存查询定义可创建兼容当前语言版本的最小清单。`manuscripts` 使用稳定书稿 ID 到工作区内 `.json` 相对路径的映射；非空注册要求 `presentation.manuscripts.v1`，且不能与清单自身或其他展示文档共用路径。`saved_queries` 同样使用稳定 ID、工作区内 `.json` 相对路径，非空注册要求 `catalog.saved_queries.v1`；它保存共享查询定义，不保存个人收藏或待办状态。`templates` 使用稳定模板 ID 到工作区内 `.json` 相对路径的映射，非空注册要求 `content.templates.v1`；每个文档只定义一个工程模板，契约见 [templates.md](templates.md)。`localizations` 使用 locale ID 到 JSON 相对路径的映射，非空注册要求 `content.localization.v1`，详细格式见 [localization.md](localization.md)。路径越界、无效注册或缺少能力时产生 WS004/WS003 并阻止受影响的写入；书稿契约见 [manuscript.md](manuscript.md)，查询见 [catalog.md](catalog.md) §7。


本地化 locale sidecar 默认位于 `.world/localization/<locale>.json`；已有登记路径沿用清单路径。sidecar 进入 Project content baseline、备份和已注册 JSON 生命周期，不进入 runtime fingerprint，也不由 runtime 读取。注册路径与其他 authoring document 一样必须位于工作区、使用 `.json` 扩展名且不共享路径；未知 schema/required feature 按原始字节只读保留。

阅读站发布配置使用 `reader_profiles` 注册 ID 到相对 JSON 路径，非空时要求 `reader.profiles.v1`。默认路径为 `.world/reader-profiles/<id>.json`，ID 限 1–80 个 ASCII 字母、数字、下划线或连字符。缺失能力时配置文档继承只读保护；原始字节进入缓冲、完整备份、外部刷新、内容基线、撤销和保存事务，不进入 runtime fingerprint。配置保存只记录选择和稳定路由，不自动生成站点；未知可选顶层字段保留，未知 schema/必需能力不编辑。格式与迁移见 [reader-site.md](reader-site.md)。

注册项的同文件身份检查只在一次清单解析内复用已打开的文件句柄，最多保留 512 个（含清单），避免几百份展示文档每次逐对重复打开。句柄在身份比较期间保持打开；不得跨解析或外部刷新缓存身份。任一路径无法打开或超出上限时，立即释放本次缓存，并对当前及后续注册项恢复逐对检查。优化不减少路径边界、大小写别名或硬链接重用的安全检查，不改变缺失新文档、未知能力只读及原始字节保留行为；浏览器仍只使用已授权快照的既有路径检查。

两类文档共享修改、外部刷新、保存基线和撤销语义。删除先成为内存墓碑；编译、搜索和导出排除墓碑，include 指向待删除源码时产生 A105，不从磁盘重新载入该源码。保存成功才推进基线；撤销已保存的新建或删除仍产生相对于当前磁盘的未保存修改。外部清单的注册变更在一次刷新中生效，本地未保存修改遇到外部变化时保留缓冲并报告冲突。

展示文档显式创建，不隐式接管已存在的普通文件。未知必需能力或不支持的格式版本禁止修改和删除；仍可按原始字节另存副本。

已有语言与资料能力可经 core 的显式预览/应用事务启用；它复用当前已应用稿、内容基线、外部冲突与 Project 快照撤销，不自动保存或升级。完整版本目录、全文新语义诊断、原始清单字节保留及存档兼容契约见 [language-versions.md](language-versions.md)。

清单注册诊断使用现有 `Diagnostic` 结构，文件位置指向清单（无法定位字段时使用首行），不混入语言编译结果：`WS001` 表示 JSON 格式或顶层结构错误，`WS002` 表示不支持的格式版本，`WS003` 表示不支持或格式错误的必需能力，`WS004` 表示无效注册项。消息为中文，严重级别为 error；错误阻止相应注册或编辑，但不丢弃原始文件。

Project 为外部刷新维护会话代次。`restore` 只接受同一工作区、同一刷新代次的快照，否则返回 false 并保持当前内容。保存本地修改不使快照过期，因此保存后的撤销仍有效。另存与导出允许把冲突中的本地缓冲保存为新目录或包，供人工合并；不会覆盖原工作区的外部版本。这条救援路径不等于冲突已解决。

## 可恢复保存

桌面保存先预检全部目标，再记录 `.world/.transactions/<id>/journal.json` 的 prepared/applying/committed 状态、相对路径、前后内容指纹及原始待写字节。缺失文件与空文件有不同指纹状态。逐文件替换失败后保留日志，打开或刷新先恢复；当前内容只在符合前状态时重做，符合后状态时跳过，第三方内容保持原样并报告冲突。自身恢复推进对应保存基线，后续本地编辑仍保留为脏内容。

未解决事务不同于普通外部刷新冲突：它阻止普通保存、另存和打包，避免把半完成事务当作一致工程。`recovery_drafts` 显式读取经校验的事务原稿、删除意图和前后/当前指纹；`export_recovery_drafts` 将它们写到工程外的新救援目录，附 `recovery.json`，供人工合并。救援不会覆盖原工作区、清理事务或宣布冲突解决；用户可按日志将冲突目标恢复为前状态或选定后状态，再重新打开完成恢复。

本模块验证写入失败、替换失败和进程中断后的恢复；不承诺磁盘损坏或掉电后所有目录元数据仍持久。文件内容同步失败会报告错误，支持目录同步的平台同时同步目录元数据；不宣称跨文件原子性。

## 本地检查点与受保护恢复

`Project::create_checkpoint(label, limits)` 显式捕获当前 `.wl` 与已注册展示文档缓冲，以及工作区内其余普通文件的原始字节。新增、删除、空文件、坏 UTF-8 展示文档、未知字段和未知格式均按文件快照保留；创建不会保存作者文件、推进 core 保存基线或改变运行指纹。格式 v2 同时捕获每个受跟踪 `.wl` 的创建时保存基线，包括明确不存在的基线；若基线与检查点正文相同则复用检查点负载，不同版本才另存。未由 Project 跟踪的 `.wl` 附件不假定有基线。配额按实际存储的正文与额外基线字节计算。v1 记录没有基线，仍可按原契约恢复，但不能声称具有三方文本对齐。检查点存放在 `.world/.checkpoints/v1/`，是本机工具状态，不进入 `workspace_snapshot`、`export_files`、另存工程包或运行语义。桌面记录跨会话保留；WASM core 记录按 Project root 与不进入作品文件的检查点会话 identity 分区，并保存在当前模块内存。浏览器编辑器将有界的检查点快照与工程快照一起放入本地保存 envelope；重新挂载/刷新后，以同一 identity 校验并恢复记录。检查点创建、删除或恢复后尝试写入该 envelope；普通工程保存也会包含检查点快照。序列化检查点快照最多 3 MiB，浏览器自身配额仍可能更低。存储写入失败不推进本地快照修订、不删除当前模块中的稿件或检查点，并提示导出工程 ZIP 作为作者文件恢复副本；下载只是导出请求，不证明持久化成功，也不包含本机检查点历史。旧 envelope（裸 ZIP base64 与 v1 session envelope）仍可打开，但没有检查点内容可恢复。外部导入的目录或 ZIP 建立新会话。

默认配额为 20 条、单条原始负载 64 MiB、总历史原始负载 256 MiB；调用方可设置更低上限。单条检查点最多 4096 个工作区文件与 4096 个保存基线，标签最多 120 个字符。配额只计算实际存储的文件与差异基线字节，不含清单与存储开销。达到数量、文件数或字节上限时创建失败，不自动淘汰旧记录；只有显式删除才释放配额。记录清单和每个负载都有版本、字节数与 FNV-1a-64 校验。该校验用于发现意外损坏，不是安全签名。无法校验的完整记录列为不可用、不得预览/恢复，并仍计入数量配额；不完整暂存记录不列为可恢复记录。

`Project::list_checkpoints()` 只读列举记录；`Project::preview_checkpoint_restore(id)` 生成逐文件新增/修改/删除差异，并列出变更 `.wl` 文件关联的对象。对象影响由 core 对完整当前与检查点源码集合各编译一次得到；任一候选含语法错误、源码字节无效或清单注册诊断时标明不完整，不推断为空。v2 检查点还投影逐段三方文本差异：`base` 是捕获检查点时每个受跟踪源码的已保存基线（明确不存在的保存基线作为空侧），`current` 是预览时 Project 缓冲，`checkpoint` 是所选记录的源码。未跟踪 `.wl` 附件和 v1 记录没有可用基线，标记 `base_available=false` 并只提供有界原文回退。此比较基线只表示确定捕获的三份内容，不声称是因果历史图中的共同祖先，也不授权合并；UI 必须如此标注。段落无法无歧义对齐或任一侧无法解码时设置不确定标志、回退到有界的三方原文片段，不伪造范围；非法 UTF-8 以明确的字节转义预览。每个计划最多投影 32 个 `.wl` 文件；每文件最多 256 项，差异文本合计 16 KiB，每侧原文片段 16 KiB。阈值见 [presentation.md](presentation.md) §11。恢复计划绑定 Project 内容基线、完整当前工作区与磁盘摘要、检查点摘要及文本投影；恢复前 core 重建整个计划并比对，因此过期或被改动的差异也不能授权写入。`Project::restore_checkpoint(plan)` 在写入前重新校验计划、只读状态、保存基线和所有相关摘要；过期、外部变化、只读目标、坏记录或配额/存储错误均不得部分改写 Project 缓冲。通过检查后，恢复是显式写入并复用可恢复保存事务；成功后刷新 Project，使恢复内容成为新的保存基线，正常报告运行指纹变化。跨文件物理写入不承诺原子性，故障交由既有事务日志恢复。

删除使用 `Project::delete_checkpoint(id)` 显式执行。不会因容量压力自动删除历史。恢复与创建失败时保留当前稿件；检查点本身在完整记录发布前不可见。存储布局、额度、浏览器保留范围及校验契约见 [ADR-0004](../docs/adr/0004-local-checkpoints.md)。

共享查询的显式排序使用查询文档级 `catalog.query_sort.v1` 能力（不加入工程清单），以及内层 query schema_version 2；旧版只读保留该文档且拒绝执行未知查询版本。恢复默认并保存时仅清除本功能排序与能力声明，见 catalog.md §7.1。

### 语言 1.12 显式持续资料约束

清单 `language_version: "1.12"` 显式启用 `schema`/`field`/`bind`；默认 1.9 与显式 1.10/1.11 不升级。未知语言版本仍按既有工作区只读保护保留原文。schema 不将旧模板转换为强约束，不扩大 `content.object_refs.v1` 的引用 kind；强 ref 属性仍需原能力声明。静态 schema 与绑定不进入运行指纹，进入源码内容基线与 Project 快照撤销；诊断/编辑影响和发布阻断见 [schemas.md](schemas.md)。

显式语言 1.13 可在 `content.object_refs.v1` 与新增 `content.character_refs.v1` 双能力保护下使用静态人物属性引用、`ref character` 约束及人物模板字段；完整兼容、改名和发布边界见 [character-refs.md](character-refs.md)。

## 稳定 ID 安全重构与逐处预览

`Project::plan_rename_target` 生成只读、不可拆分的全工程计划；`apply_rename_plan` 整批提交内存缓冲，保存继续使用既有事务。entity/relation 的声明、别名、显式 ref、正文/选项链接、关系端点、状态所属对象、mark/attach/anchor_link、scope_ref 与 schema bind 只替换 core 正式词法/语法提供的身份 token 范围。普通文字、注释（含同一行与跨行块注释）、引号显示名、转义、Unicode、相似 ID，以及链接 label 的原始字节均保持不变。不通过整行字符串替换推断引用，不在 UI 建立第二套解析器。

每个 `RefactorChange` 保留 path/kind/reference_count，新增 `occurrences`。每一处含 `line`（1 起）、`field`（源码语义字段或 JSON Pointer）、`before_range` / `after_range`（整份文档 UTF-8 字节半开范围，start/end）、`before_token` / `after_token`、`before_context` / `after_context`（真实前后完整行）。计划保留 target/new_id/content_baseline/changes/explicit_references，新增 `runtime_fingerprint_before` / `runtime_fingerprint_after`（u64）。逐处预览、范围及候选字节来自同一次真实编辑；注册 JSON 也只定位既有受支持引用字段，保留无关字节、扩展字段及排版。字段名改动以该键的 JSON Pointer 标识，不把同值普通字段视作引用。

预览绑定完整内容基线。应用时重新生成完整计划，并比较全部身份、位置、语境、前后字节及引用数；删减文件、修改 token/语境或篡改目标均拒绝，不提供任意排除某一引用的接口。取消、陈旧预览、磁盘外改、只读文件、无效候选或被篡改计划均零修改。没有有效候选时不提供可提交的预览。

entity/relation 改名仍要求运行指纹完全相同；其中作为 state 所属对象的 entity 稳定 ID 是运行身份的一部分，并非纯静态资料。若候选改变指纹，安全拒绝并列出受影响 state 的 ID、声明文件/行及旧/候选指纹，解释旧 Story 存档与检查点的指纹不匹配、不能直接载入候选；入口 trace 按 [replay.md](replay.md) 允许在新指纹上重新受控验证，不能保证沿用；建议保留稳定 ID、仅修改 entity 的 `as "显示名"`。本功能不增加迁移模式，不修改旧 save/replay，不移除 state target 指纹，不放宽载入守卫。

关系定义不采用实体的 `as` 显示名语法；如需变更关系称呼，可保留稳定 ID、编辑对象别名。当前状态分析不接受 relation 作为有效所属对象，仍报告原有 A216，不因本轮重构扩大语言支持。

既有 rule/fragment/character/tag/state 改名保留原语法改写与 `reference_count` / `explicit_references` 身份引用计数。若旧语法必须重编码整条引号语句，逐处项以 `field: "source.syntax"` 标识真实整行语法变更范围；一项可包含多个身份引用，不能把逐处项数冒充旧引用计数。entity/relation 始终投影精准身份 token，不使用该回退。

## 安全源码新建、引用与路径移动（工具 0.16）

新建活动源码与引用既有源码是不同操作；显式 source_sets 新建同时加入 active，引用
归档/非活动源码须拒绝且不自动启用。单个非入口源码路径移动使用统一只读计划、整体
重校验、一次内存事务及既有保存 journal；正式字段清单、等价证明、拒绝边界和机器
DTO 见 [source-lifecycle.md](source-lifecycle.md)。

工程问题报告是覆盖活动内容、清单和十类已注册创作文档的只读快照；未注册普通文件不接管、原始字节不改写，完整范围/精度/不完整状态见 [problems.md](problems.md)。
