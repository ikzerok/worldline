# Markdown 资料迁移契约

CAP-07A 首版把外部 Markdown 页面迁移为语言 1.10 的实体资料；它不是通用 Markdown 转换器，也不修改来源文件。实现、CLI 与 JSON-RPC 共用 core 的预览和应用 DTO。

## 输入与边界

输入是用户明确选择的普通目录快照。递归扫描按规范相对路径排序；拒绝符号链接、Windows 联接、特殊文件、路径穿越、无效 UTF-8、远程资源和超出 [presentation.md §11](presentation.md#11-阈值登记单源) 预算的输入。读取器不得跟随输入目录之外的路径。预览不写工程或输入目录，不推进 Project 基线。

来源树目录与文件合计最多 2048 项，文件最多 512 个；导入命名空间最多 64 UTF-8 字节。来源相对路径和生成的目标相对路径最多 512 UTF-8 字节，每个路径分量最多 200 字节；拒绝 Windows 保留设备名、控制字符、大小写折叠冲突及不能跨平台安全保存的路径。阈值统一见 [presentation.md §11](presentation.md#11-阈值登记单源)。

每个 `.md` 文件创建一个 `entity`，`kind` 默认 `lore`。仅支持以下 front matter 标量：

```yaml
---
id: harbor
title: 雾港
kind: place
---
```

标量可使用未转义的普通文本或单/双引号包裹；重复键、无法解码的值阻止应用。未知 front matter 字段列入损失报告，并随原文副本保留。缺少 `title` 时取第一个一级标题，再退回文件名；显式 `id` 必须符合语言标识符规则。未提供 ID 时，以规范相对路径 UTF-8 字节的 FNV-1a 64 位哈希生成 `md_<16 位小写十六进制>`。同名页面永不自动合并；ID 冲突列出候选，必须通过显式映射选择。名称相同但 ID 不同的页面会单独提示。

支持 ATX 标题、普通段落、相对 Markdown 链接、相对附件链接和图片链接。段落软换行折叠为空格；实体说明保留可见文字。标题创建稳定 `anchor` 并关联所属实体。指向本次导入页面的链接写成 `markdown_link` 类型的有向关系；带有效标题片段的链接指向标题 anchor。链接标签作为关系说明，来源路径与行号作为 `source_note`。同一工程中已存在的不兼容 `markdown_link` 类型是明确 ID 冲突；不能静默复用。

相对附件被复制到导入命名空间下并登记为 `asset`；不改变附件原字节。来源 Markdown 原文同时复制为只读审阅副本，保留未知语法与来源追踪。路径必须在来源目录内，目标不得碰撞工程既有文件。无效或缺失的页面链接、片段和附件在预览中逐项说明；不能声称它们已映射。

不执行或下载 HTML、脚本、宏或远程资源。HTML、围栏代码、表格、未知 front matter 和丢失的格式信息逐项进入损失报告；正文中无法转换的内容保留于原文副本，不可静默删除。隔离项目不得作为语言声明、附件或执行输入。

## 预览与应用

`Project::preview_markdown_import` 对当前 Project 与整个来源快照建立只读候选，报告稳定 ID 映射、名称/ID/路径冲突、链接映射、损失、所有待写文件及当前内容基线。若目标仍为 1.9，预览必须显式标出升级到 1.10；应用需单独确认此升级。损失项目也必须显式确认后才能应用。预览不得自动消解冲突或合并同名条目。

预览计划绑定来源路径、来源文件字节摘要、目标 Project 内容基线、每个目标文件的缺失/字节基线和映射选项。应用重新扫描并重算计划；任一摘要或基线不同、冲突未解、只读诊断、来源或附件失效、编译新增错误、目标只读/已存在或保存事务失败，均拒绝整个候选。候选应用将所有新源码、清单与普通附件交给 Project 一次保存；磁盘层遵守 [workspace.md](workspace.md) 的可恢复保存事务，不宣称文件系统具备多文件原子替换。

导入命名空间和所有创建路径均来自 core 生成的安全相对路径；调用端不得自行拼接写入路径。CLI `markdown import preview|apply` 与 RPC `markdown.import.preview/apply` 只转发到同一 core API。预览 JSON 是审阅信息，应用必须携带预览摘要、内容基线、显式 ID 映射和损失/语言升级确认。
