# 书稿编排文档契约

版本 1，CAP-02A 核心契约。书稿是工作区中的展示文档，用稳定章节 ID 和既有 `TargetRef` 排列阅读材料。它不复制 `.wl` 正文，不生成内容对象，不改事件顺序、世界时间、运行出口或存档指纹。

## 注册与兼容

工作区清单通过 `manuscripts` 对象注册书稿，键为书稿 ID，值为工作区根目录内的相对 JSON 路径，例如：

```json
{
  "schema_version": 1,
  "required_features": ["presentation.manuscripts.v1"],
  "manuscripts": {
    "novel": ".world/manuscripts/novel.json"
  }
}
```

书稿路径必须是工作区内相对 `.json` 路径，不接受绝对路径、目录联接或越界路径。不同注册项不能共享同一物理文件。没有清单或没有 `manuscripts` 注册项的旧工程保持原样，不扫描普通 JSON，也不隐式迁移 1.9 工程。未知必需能力或未知格式大版本使文档只读；原始字节仍可另存。书稿文档采用 UTF-8 JSON，顶层含 `schema_version: 1`、与清单键一致的 `id`、显示 `title` 和 `entries` 数组。

机器可读形状见 [manuscript.schema.json](schemas/manuscript.schema.json)；该 Schema 不替代 core 的跨文档路径、唯一 ID、父项/环路及正文引用校验。

读取层必须保留原始字节及所有未知可选字段。投影 DTO 只含已理解字段，禁止将 DTO 整体序列化覆盖源文档。结构编辑只更新指定字段，并保留顶层及节点上的未知字段；应用前检查完整 Project 缓冲和每个已跟踪文件的磁盘保存基线。预览不推进 Project、保存基线、撤销栈或磁盘状态。新建书稿时显式创建或更新清单注册和文档；已有书稿编辑只更新书稿文档，不重排或格式化清单。

## 章节树

`entries` 是平坦数组；数组中同一父项的先后顺序就是阅读顺序。节点形状如下：

```json
{
  "id": "chapter_opening",
  "kind": "chapter",
  "parent_id": "volume_one",
  "title": "雾港",
  "target_ref": {"kind": "scene", "id": "arrival.harbor"},
  "summary": "旅人抵达港口。",
  "pov": {"kind": "character", "id": "traveler"},
  "status": "draft",
  "goal": "建立港口氛围"
}
```

`kind` 只允许 `section` 或 `chapter`。`section` 可有 `parent_id`、`summary`、`status` 和 `goal`，但不能引用正文或声明 POV；`chapter` 可位于根或某个 section 下，必须有 `target_ref`，不能作为其他节点的父项。`parent_id` 省略或为 `null` 表示根节点。章节的 `summary`、`pov`、`status`、`goal` 可选；`pov` 必须引用现存 `character`。显示标题、摘要、状态和目标可编辑，不能充当身份。ID 必须以 ASCII 字母或 `_` 开头，后续字符限 ASCII 字母、数字、`_`、`-`；同一书稿内唯一，重排、改标题或改目标不得改变它。

父项必须存在且为 `section`。拒绝重复 ID、悬空父项、自引用和环形层级；损坏节点保留在原始文档中并产生诊断，不能借修复树的名义删除章节。树遍历采用数组顺序的深度优先前序；读序完全独立于 timeline 偏序和事件执行出口。

## 正文引用与来源边界

`target_ref` 只允许引用当前分析中可确认存在的 `event`、`scene` 、1.10 `entity` 或显式 1.11 `fragment`。事件章节引用整个事件体；场景章节使用完整场景 ID（如 `arrival.harbor`），引用该场景及其子场景；实体章节引用其 `description`，片段章节引用片段声明体。规则是纯表达式声明，不作为章节正文来源。1.11 工程已有语言版本/必需能力门控，旧客户端仍只读保留。不允许文件路径、行号、显示名或数组位置作为身份，不保存正文副本。章节重排、摘要/POV/状态/目标编辑只写书稿字段。源对象改 ID 或删除时，引用必须进入引用影响报告；无法确认源码对象的解析快照属于 unresolved，不能误报为已删除。悬空引用产生诊断并保留章节，不能级联删章。

静态投影只抽取事件、场景或片段内 `TextStmt` 的字符串字面量和显式链接标签、选项标签；实体只投影 `description`。1.11 `say` 仅统计台词文本，不计 speaker 或演出备注；`call` 在作者预览中显示片段引用但不递归展开、执行参数或累计被调用文本。多个条件分支与选项的静态文本按源码顺序都计入，因为书稿引用源码，不声称模拟某次运行。插值表达式、条件、变量声明、跳转、效果、状态变更、锚点、事件摘要及章节元数据均排除，不求值、不执行。投影只返回目标种类/ID、源文件与声明行、可用性和统计；core 不复制源码缓冲。

统计口径固定如下：

- 汉字数是抽取文本中的 CJK 统一表意文字与兼容表意文字 Unicode 码位数，扩展区按当前实现覆盖的码位范围计算；标点、假名、注音、emoji 和语法代码不计。
- 词数中每个汉字计一个词；每段连续的非汉 Unicode 字母或数字计一个词。空白、标点、emoji 分隔词且不计数。不做自然语言分词、词干还原或变量插值。
- “代码排除”通过抽取规则保证：统计只接收上述用户可见静态文本；语法、表达式和其他源码字符不会进入计数。该数字不表示实际游玩时出现的文本量。

## 投影分页与诊断

core 从同一不可变分析快照生成扁平章节投影页，携带书稿/章节稳定 ID、父 section 路径、顺序、目标、元数据、来源定位、引用状态及可用统计。页使用从零开始的偏移和请求条数，单页上限 100；`next_offset` 只对同一文档与分析快照有效。缺失来源的章节仍占其阅读顺序位置，统计与来源定位为空。

书稿诊断使用 `Diagnostic`：`MAN001` 表示 JSON 或结构错误，`MAN002` 表示未知能力或不支持的版本并按只读处理，`MAN003` 表示在无编译错误的完整分析中确认目标不存在，`MAN004` 表示因编译错误或语言版本限制而无法确认目标，`MAN005` 表示节点 ID 重复，`MAN006` 表示父项非法，`MAN007` 表示层级成环，`MAN008` 表示目标类型或 POV 类型非法。消息中文，诊断不混入故事编译结果。错误诊断不得清除原始文档或隐藏仍可识别的章节。

## 指纹与生命周期

书稿、章节顺序、摘要、POV、状态、目标和统计都不进入 `Program` 或运行指纹。章节引用既有内容，不创建第二份内容真源。旧 1.9 工程没有书稿注册时不扫描普通 JSON、不自动创建清单或能力声明；显式创建书稿才会写入注册项与 `presentation.manuscripts.v1`。未声明能力、未知必需能力或不支持的书稿格式只读保留原始字节。

Project 只从清单载入注册书稿，并纳入 `authoring_documents` 的保存基线、刷新冲突、撤销、另存和导出。`preview_manuscript` 不落盘；`apply_manuscript` 同时检查调用方修订、当前 Project 缓冲及所有已跟踪文件的磁盘基线，成功后作为一个 Project 候选整体提交。删除影响计划列出书稿来源/POV 引用；删除被场景章节引用的事件同样受阻。稳定 ID 重命名改写受影响的已注册展示 JSON，并校验新 ID 解析成功且旧引用消失。无效或不完整的注册/书稿诊断阻止以不完整结果授权删除或重命名。

core 公共 API 提供按清单索引书稿、树前序分页、静态来源统计，以及带基线的预览和应用命令。书稿创建/编辑不生成源码或新内容实体；成功写入不会改变运行指纹。撤销使用 Project 快照，磁盘保存与目录导出继续由统一 Project 生命周期负责。

## 正文中心工作区与安全重组（0.8）

正文工作区按源文件持有一个 core `WritingBuffer`；同一文件的多个章节、正文块、结构视图和完整源码视图都投影这个缓冲，不另存章节正文副本。打开章节先以稳定 `TargetRef` 定位当前 event/scene 的声明体；不从整个文件开头代替章节正文。实体来源仍保留，但其属性结构通过原文视图编辑。core 根据既有词法/分析结果提供字节范围和正文/结构块，UI 不解释 DSL。简单正文块保留原始内插、链接、转义、本地化 ID 和注释；编辑器明确这些内联标记是源文的一部分。结构行只读展示，可切到当前目标结构或完整源码编辑，未知语法不被表单重建。

缓冲携带完整 Project 内容基线、源文件身份、原始文本和递增编辑代次。每次范围修改同时检查代次与原文片段，过期投影不得写入。目标范围无法确认或草稿有编译错误时暂停块编辑，完整源码仍可继续修改；原文及无效草稿完整保留。预览、切章、切模式不修改 Project、磁盘或撤销栈。应用重新校验 Project 基线、工作区可写性及全部磁盘保存基线，正文/结构范围应用要求候选编译通过；明确的完整源码应用 `apply_source_writing_buffer` 则允许诊断，返回诊断且保留全部原稿，便于未完成作品保存。两种应用均整体提交为一次可撤销操作，完整源码通道不绕过基线、只读或磁盘冲突。`open_source_writing_buffer(path)` 可打开已载入的无效源码，以及新增/更新 rule、fragment 的所在文件，不依赖目标解析；新文件仍先通过统一工作区创建接口显式加入。失败保留整个缓冲，不部分提交。取消只关闭当前动作；明确丢弃才恢复该文件草稿。外部改动不自动把脏稿重基线到新内容。个人会话只记录稳定书稿/章节身份、滚动和光标位置，不写入共享书稿或运行指纹；光标仅在目标与完整源文指纹一致时恢复，不保存正文副本。连续同缩进正文与空行合并为同一编辑块，避免按行重建打断连续输入。

书稿重组继续使用 `preview_manuscript` / `apply_manuscript`。同父项上移/下移为既有能力；移动到分节保留稳定 ID，移动分节时所有后代随其父链移动，拒绝自己/后代作为新父项。删除编排项必须先显示受影响章节/分节并明确确认；分节删除包括其编排后代，但不删除任何 `.wl` 对象、正文或文件。删除/移动只形成待应用草稿，恢复草稿零写；应用为一个事务，未知字段沿用原文合并规则。新章节必须明确选择来源，不能默选目录第一项。可折叠树、摘要/POV/状态/静态字数/目标卡片与状态/POV筛选均为展示，不改变数据语义；树折叠和筛选只保存个人视图状态。静态字数与阅读预览不代表任一实际运行路径。

## 0.9 当前稿阅读与专注工作台

书稿阅读默认范围为当前章节；作者可明确切换整书。编辑与阅读各有独立滚动区，宽屏在当前可用宽度足够时并列，窄屏退化为“编辑 / 预览”标签，不以覆盖正文的浮窗假装并列。专注模式只常驻章节身份、模式、草稿状态和主要动作，书稿编排、来源完整路径与说明在二级控件中展开；导航隐藏、双参考和个人字号/主题能力继续保留。

`Project::compile_writing_drafts` 将按文件唯一的当前 WritingBuffer 只读叠加到工程副本，检查相同基线及重复路径冲突，再复用统一 compiler。有效输入由 core 静态阅读投影，正文、强链接、台词和片段调用说明保持既有静态含义，不执行选择或表达式，不读取 runtime 状态、不耗 RNG、不应用、不保存。多个章节共享同一源文件时只应用该文件一个缓冲。未变化的缓冲不覆盖较新工程。

当前输入无效、目标不可定位或基线冲突时，预览必须明确显示“预览过期”及错误原因；可显示同一稳定目标的上次有效只读投影，必须标明它不是当前稿。没有同目标有效投影时显示不可预览，不借用别的章节快照。无效输入与选中章节保留，修复后自动恢复当前稿投影。整书预览仍逐章使用已明确编排的来源，不因参考或链接扩大范围。

## 当前稿选区批注（0.11）

写作、结构、源码模式复用已验证的显示字符到源 UTF-8 字节映射；只对当前来源/目标/源快照一致的非空选区提供批注。CommentDocument v1 按行锚定，因此预览明确显示扩展后的整行原文与真实来源，不声称字符级锚点。未应用正文必须先由作者明确应用，再重新选择；点击批注不自动应用或保存。批注编辑中的输入独立保留，不能因切章、导航或筛选而静默删除。书稿正文/编排与批注的撤销层继续分离。
