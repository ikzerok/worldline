# 书稿编排文档契约

版本 1，CAP-02A 核心契约。书稿是工作区中的展示文档，用稳定章节 ID 和既有 `TargetRef` 排列阅读材料。它不复制 `.wl` 正文，不生成内容对象，不改事件顺序、世界时间、运行出口或存档指纹。

## 注册与兼容

工作区清单通过 `manuscripts` 对象注册书稿，键为书稿 ID，值为工作区根目录内的相对 JSON 路径，例如：

```json
{
  "schema_version": 1,
  "required_features": ["presentation.manuscripts.v1"],
  "manuscripts": {
    "novel": ".world/manuscripts/novel.json"
  }
}
```

书稿路径必须是工作区内相对 `.json` 路径，不接受绝对路径、目录联接或越界路径。不同注册项不能共享同一物理文件。没有清单或没有 `manuscripts` 注册项的旧工程保持原样，不扫描普通 JSON，也不隐式迁移 1.9 工程。未知必需能力或未知格式大版本使文档只读；原始字节仍可另存。书稿文档采用 UTF-8 JSON，顶层含 `schema_version: 1`、与清单键一致的 `id`、显示 `title` 和 `entries` 数组。

机器可读形状见 [manuscript.schema.json](schemas/manuscript.schema.json)；该 Schema 不替代 core 的跨文档路径、唯一 ID、父项/环路及正文引用校验。

读取层必须保留原始字节及所有未知可选字段。投影 DTO 只含已理解字段，禁止将 DTO 整体序列化覆盖源文档。结构编辑只更新指定字段，并保留顶层及节点上的未知字段；应用前检查完整 Project 缓冲和每个已跟踪文件的磁盘保存基线。预览不推进 Project、保存基线、撤销栈或磁盘状态。新建书稿时显式创建或更新清单注册和文档；已有书稿编辑只更新书稿文档，不重排或格式化清单。

## 章节树

`entries` 是平坦数组；数组中同一父项的先后顺序就是阅读顺序。节点形状如下：

```json
{
  "id": "chapter_opening",
  "kind": "chapter",
  "parent_id": "volume_one",
  "title": "雾港",
  "target_ref": {"kind": "scene", "id": "arrival.harbor"},
  "summary": "旅人抵达港口。",
  "pov": {"kind": "character", "id": "traveler"},
  "status": "draft",
  "goal": "建立港口氛围"
}
```

`kind` 只允许 `section` 或 `chapter`。`section` 可有 `parent_id`、`summary`、`status` 和 `goal`，但不能引用正文或声明 POV；`chapter` 可位于根或某个 section 下，必须有 `target_ref`，不能作为其他节点的父项。`parent_id` 省略或为 `null` 表示根节点。章节的 `summary`、`pov`、`status`、`goal` 可选；`pov` 必须引用现存 `character`。显示标题、摘要、状态和目标可编辑，不能充当身份。ID 必须以 ASCII 字母或 `_` 开头，后续字符限 ASCII 字母、数字、`_`、`-`；同一书稿内唯一，重排、改标题或改目标不得改变它。

父项必须存在且为 `section`。拒绝重复 ID、悬空父项、自引用和环形层级；损坏节点保留在原始文档中并产生诊断，不能借修复树的名义删除章节。树遍历采用数组顺序的深度优先前序；读序完全独立于 timeline 偏序和事件执行出口。

## 正文引用与来源边界

`target_ref` 只允许引用当前分析中可确认存在的 `event`、`scene` 或 1.10 `entity`。事件章节引用整个事件体；场景章节使用完整场景 ID（如 `arrival.harbor`），引用该场景及其子场景；实体章节引用其 `description`。不允许文件路径、行号、显示名或数组位置作为身份，不保存正文副本。章节重排、摘要/POV/状态/目标编辑只写书稿字段。源对象改 ID 或删除时，引用必须进入引用影响报告；无法确认源码对象的解析快照属于 unresolved，不能误报为已删除。悬空引用产生诊断并保留章节，不能级联删章。

静态投影只抽取事件或场景内 `TextStmt` 的字符串字面量和显式链接标签、选项标签；实体只投影 `description`。多个条件分支与选项的静态文本按源码顺序都计入，因为书稿引用源码，不声称模拟某次运行。插值表达式、条件、变量声明、跳转、效果、状态变更、锚点、事件摘要及章节元数据均排除，不求值、不执行。投影只返回目标种类/ID、源文件与声明行、可用性和统计；core 不复制源码缓冲。

统计口径固定如下：

- 汉字数是抽取文本中的 CJK 统一表意文字与兼容表意文字 Unicode 码位数，扩展区按当前实现覆盖的码位范围计算；标点、假名、注音、emoji 和语法代码不计。
- 词数中每个汉字计一个词；每段连续的非汉 Unicode 字母或数字计一个词。空白、标点、emoji 分隔词且不计数。不做自然语言分词、词干还原或变量插值。
- “代码排除”通过抽取规则保证：统计只接收上述用户可见静态文本；语法、表达式和其他源码字符不会进入计数。该数字不表示实际游玩时出现的文本量。

## 投影分页与诊断

core 从同一不可变分析快照生成扁平章节投影页，携带书稿/章节稳定 ID、父 section 路径、顺序、目标、元数据、来源定位、引用状态及可用统计。页使用从零开始的偏移和请求条数，单页上限 100；`next_offset` 只对同一文档与分析快照有效。缺失来源的章节仍占其阅读顺序位置，统计与来源定位为空。

书稿诊断使用 `Diagnostic`：`MAN001` 表示 JSON 或结构错误，`MAN002` 表示未知能力或不支持的版本并按只读处理，`MAN003` 表示在无编译错误的完整分析中确认目标不存在，`MAN004` 表示因编译错误或语言版本限制而无法确认目标，`MAN005` 表示节点 ID 重复，`MAN006` 表示父项非法，`MAN007` 表示层级成环，`MAN008` 表示目标类型或 POV 类型非法。消息中文，诊断不混入故事编译结果。错误诊断不得清除原始文档或隐藏仍可识别的章节。

## 指纹与生命周期

书稿、章节顺序、摘要、POV、状态、目标和统计都不进入 `Program` 或运行指纹。章节引用既有内容，不创建第二份内容真源。旧 1.9 工程没有书稿注册时不扫描普通 JSON、不自动创建清单或能力声明；显式创建书稿才会写入注册项与 `presentation.manuscripts.v1`。未声明能力、未知必需能力或不支持的书稿格式只读保留原始字节。

Project 只从清单载入注册书稿，并纳入 `authoring_documents` 的保存基线、刷新冲突、撤销、另存和导出。`preview_manuscript` 不落盘；`apply_manuscript` 同时检查调用方修订、当前 Project 缓冲及所有已跟踪文件的磁盘基线，成功后作为一个 Project 候选整体提交。删除影响计划列出书稿来源/POV 引用；删除被场景章节引用的事件同样受阻。稳定 ID 重命名改写受影响的已注册展示 JSON，并校验新 ID 解析成功且旧引用消失。无效或不完整的注册/书稿诊断阻止以不完整结果授权删除或重命名。

core 公共 API 提供按清单索引书稿、树前序分页、静态来源统计，以及带基线的预览和应用命令。书稿创建/编辑不生成源码或新内容实体；成功写入不会改变运行指纹。撤销使用 Project 快照，磁盘保存与目录导出继续由统一 Project 生命周期负责。
