# 工程模板 v1

工程模板是作者资料表单的描述，不是实例的语义来源。内置目录仍由
[`templates.catalog.json`](templates.catalog.json) 定义；已有
16 个内置模板 ID（如 `template_place`）保持不变，工程模板使用
`project:<ID>` 命名空间，不能覆盖或改写内置项。工程清单 `.world/project.json`
的 `templates` 对象把稳定模板 ID 映射到工作区内相对 `.json` 路径。非空注册必须
声明 `required_features` 中的 `content.templates.v1`。每个文档只定义一个模板，注册
键必须等于文档 `id`；注册路径不得与清单或其他展示文档重用。

工程模板文档的 `schema_version` 为 `1`，包含 `id`、`title`、`applies_to`、`fields`。
`applies_to.kind` 为 `world`、`character` 或 `entity`；只有 `entity` 可指定
`entity_type`。字段具有稳定 `id`、显示 `label`、`type` 和可选的实例 `key`；除
`group` 外必须提供 `key`。`required` 表示模板表单完整性提示，不会自动补值或改写
现有实例。字段 ID 在整个模板中唯一；实例 key 在模板中唯一，包括不同分组。

字段 `type` 为 `text`、`number`、`boolean`、`enum`、`object_ref` 或 `group`：

- `text`、`number`、`boolean` 分别对应字符串、有限数值和布尔属性。
- `enum` 的 `choices` 必须非空、无重复且不含空白项；实例值仍是字符串。
- `object_ref` 必须指定 `target.kind` 为 `entity` 或 `relation`，或显式 1.13 双能力保护下的 `character`（模板文档还须声明 `content.character_refs.v1`，见 [character-refs.md](character-refs.md)）；可选
  `target.entity_type` 仅用于 `entity`。目标限制为 core 可完整重命名和保护删除的上述类型。
  实例必须使用下文的显式 `ref("kind", "id")` 属性值；普通字符串即使内容相同
  也不是对象引用。默认值以 `{"kind":"entity","id":"harbor"}` 的 TargetRef
  形状保存，并且目标必须存在且符合 `target` 约束。引用按完整 `TargetRef` 参与验证、
  目录、重命名与删除影响。其他 TargetRef 类型暂不支持模板对象引用，必须由 core
  定位诊断拒绝。
- `group` 仅是界面分组，不对应实例属性；必须有非空 `fields`，不能有 `key`、
  `required`、`choices`、`target` 或 `default`。子字段继续遵循相同规则。

字段可选包含 `default`，其类型必须符合字段类型（`enum` 默认值必须属于
`choices`）。默认值只作为表单提示，不代表实例属性存在；未设置属性、显式
`null`（若其他资料来源保存了它）和模板默认值是不同状态。模板 API 不写入实例，
也不把 `null` 转换成默认值。未知可选字段必须保留；未知 schema 版本或未知
`required_features` 使该文档只读，并保留原始字节。

导入、替换和删除必须先生成只读影响预览。预览说明字段增删、稳定 ID 对应的改名或
类型变化，并列出适用实例及字段值状态；它不修改 Project、源码、别名、属性或保存
基线。应用操作提交预览时的完整 Project 基线；基线过期、外部保存基线变化、注册或
文档只读时失败，不能部分提交。替换保留原文档中未知可选字段；删除只移除模板注册
和模板文档，不改写实例。类型变更、字段改名和缺失值不触发隐式强转或迁移。

语言属性 `object_ref` 是 1.10 的新增显式值，要求 Project 清单声明
`content.object_refs.v1`。在 1.10 工程中显式导入包含该字段的模板时，预览/应用会一并
加入此已知能力；1.9 工程拒绝导入此类型字段，且已注册的该模板只读：

```wl
entity harbor kind place as "雾港"
character navigator as "领航员"
  property home = ref("entity", "harbor")
```

目标 kind 和 ID 是字面字符串，不做表达式求值；v1 的 kind 只允许 `entity` 与 `relation`。
core 只在 `ref(...)` 值上建立强引用；
字符串属性不会被模板定义、字段同名或内容猜测提升成引用。缺失目标产生语言诊断，
并出现在引用影响、重命名和删除保护中。该属性值不进入运行指纹。1.9 不支持此值。
对象引用字段仍只是编辑提示：本票不提供可执行规则、远程资源、自动默认值、自动
迁移或自动填充。

旧 1.9/1.10 工程没有模板注册时保持原行为；模板注册不改变 `language_version`。
内置目录现有字段 `widget`（如 `multiline`）与工程模板的稳定字段 `type` 是不同
契约，不隐式迁移内置模板 ID 或旧模板目录。模板诊断 code 使用 `TPL` 前缀，message
使用中文。

显式语言 1.13 可在 `content.object_refs.v1` 与新增 `content.character_refs.v1` 双能力保护下使用静态人物属性引用、`ref character` 约束及人物模板字段；完整兼容、改名和发布边界见 [character-refs.md](character-refs.md)。

字段 target.kind 或 target.entity_type 变化属于 constraints_changed，影响预览显示实例类型是否匹配，不把既有字符串、其他 kind 或默认值写入实例。人物模板默认引用进入统一删除影响，并随人物稳定 ID RenamePlan 改写。

## 可视草稿与结构编辑（工具 0.31）

可视设计器与高级 JSON 共享同一份未应用的原始文档。新建和复制由 core 生成合法的
schema 1 文档；复制内置模板生成新的 `project:` 身份，不改变原内置目录。草稿投影
复用工程模板解析、类型和引用验证，不接管或写入 Project。实际表单试填复用实例
表单，试填值只属于编辑器会话，不写实例，不作为默认值。

core 提供字段新增、已知属性修改、删除及移动操作。字段 ID 是全模板稳定身份；
移动使用目标父组 ID（空表示根）和移除后的目标数组插入位置，不依赖显示标签。
不能将组移动到自身或后代。新分组带一个新文本子字段，避免生成空组。删除组明确
删除其全部子字段；组与普通字段不能通过类型切换隐式互换或丢掉子字段，须显式
删除后新增。普通字段类型切换只更换该字段的已知属性，界面在提交前展示最终属性。
所有操作先在独立候选文档完成；不合法的候选被拒绝，原草稿与界面输入保留。

新增字段 ID 和 key 由 core 在全模板范围内分配不重复的值。字段标签、key、类型、
required、choices、target 和 default 均通过 core 校验；稳定 ID 在可视面中只读，
高级 JSON 仍可显式改 ID（影响预览按删除/新增显示）。根元数据与字段未知可选扩展
保留。替换时按全模板的稳定字段 ID 追踪未知字段，包括跨分组移动后的 field 和
嵌套 target 扩展；不将未知扩展错配给同 key 或同显示名字段。显式删除的字段不复活。

高级 JSON 保留手工输入的原字节，切换视图和失败预览不得重新序列化或替换坏原文。
无效 JSON、重复 JSON 键、未知格式或未知必需能力不能强制转换为可视草稿；仍可
查看、复制原文和保留输入。未应用 JSON 草稿修正后仍使用既有显式导入/替换路径；
已登记的坏原文仅适用下文独立 RepairInvalid 的窄修复边界。未知格式与必需能力
维持只读，不因复制或设计器绕过。

草稿的保存基线独立于当前选择：仅浏览不产生未应用输入，新建/复制即产生未应用
草稿。可视属性输入、JSON 输入或待确认停用预览未处理时，切模板、新建、
复制、重新载入、换作品及退出必须要求明确保留或丢弃；取消保持原输入。界面只在
明确应用成功后推进草稿基线，失败不推进。应用仍复用 `TemplateCommand` 的内容/
修订/磁盘基线保护及单次撤销；应用后需保存全部才写入工作区。切换可视/JSON/试填
页不应用草稿，取消影响预览不丢字段输入。纯试填值不属于未提交作者稿，不单独
阻止退出；切换模板会明确提示试填重置，亦提供显式清空入口。

### 坏原文的显式修复

普通 Replace 继续拒绝只读旧文。独立 `RepairInvalid { id, document }` 操作仅用于旧文
诊断全部为 TPL001 且清单、注册、底层文档无继承只读的情况；新文必须完整有效，
保持原注册 ID，不能借修复绕过未来 schema、未知必需能力或语言能力限制。修复预览
必须包含 TPL007 警告：旧原文无法安全解析，确认替换会采用完整新文；旧扩展无法
合并，请先复制原文。作者通过独立修复入口及“确认完整替换坏原文”提交；默认
导入/替换不启用修复。内容基线包含原坏字节，失败保持零修改；一次撤销恢复坏原文
原字节。用户也可继续复制或完整备份原文，不必接受修复。

Existing 草稿绑定原注册 ID。高级 JSON 改 ID 后，普通预览拒绝身份不一致；作者可
显式选择“按 JSON 身份导入 / 替换”，新 ID 未注册则导入另一模板，已注册则预览
替换该确切身份。原模板不会被隐式删除；字段 ID 在 JSON 中改动仍按新增/删除显示。

RepairInvalid 的坏文保护元数据必须可确认：仅完整结构化可读、根级每次
`schema_version` 均为 1 且至少出现一次、每次 `required_features` 都为合法受支持
数组的重复键原文可原地修复。元数据缺失、解析中断或任何出现值未知时拒绝；语言
及对象引用能力继承保护继续适用。无法原地修复时保留原字节，作者可先复制原文，
再把有效新文显式按新身份导入。

字段影响预览还比较稳定 ID 的直属父组与同级位置。移动/重排产生
`position_changed`，并给出 `old_parent_id`、`new_parent_id`、`old_index`、
`new_index`（索引从 0 开始，父组为空表示根层）。位置变化不表示实例属性迁移。
同一字段有结构位置与已知属性同时变化时，位置变化另列一项，不能因类型或标签变化
而漏报；无变化的字段不产生伪变更。

草稿线协议还携带可选 `reserved_field_ids`、`reserved_keys` 字符串数组，缺省为空。
这是当前草稿的已使用身份/属性名保留集合，排序去重，不写入模板文档或作品 schema。
core 新建/载入时记录已见名称；成功结构操作合并当前和候选名称，失败不推进。
自动新增还合并绑定 Project 原模板的所有字段 ID/key，旧调用方省略保留集合时也
不能重用原模板中刚删除的身份。高级 JSON 坏输入、切视图、取消和本地草稿撤销保留
已知集合；序列化恢复同一草稿继续避让。显式 JSON 改 ID/key 仍按作者提供的身份
解释，不把保留集合当作权限或替换目标。保留集合计入机器请求总预算。

### 影响预览的完整性与适用范围

正式预览携带 `complete` 与可选 `incomplete_reason`。`check_integrity=true` 时，core
必须检查同一当前源码编译结果并保留其诊断；缺失 include、语法错误或其他编译错误
会令影响不完整。可保留已知对象行，但必须标明它们不是全部实例，不能把零行当作
“没有影响”。`check_integrity=false` 仅表示未做完整检查，必须标为不完整而不是
默认通过。core 应用拒绝不完整预览，新编辑器与机器入口都不能以它授权提交；
本地定义草稿和原文保留，修复来源后重新预览。

每个实例影响行携带 `current_applicable`、`proposed_applicable`：分别按旧/新模板的
实际 kind 与可选 entity_type 判断。旧新适用对象取并集，仅向该对象适用的一侧投影
字段值，不把退出范围的对象按新类型报告 TypeMismatch，也不把新进入对象当作旧
模板实例。模板缺省的一侧不适用；引用、required/default 仍不写入真实对象。

预览的 `current_template`、`proposed_template` 为 core 生成的可选简要元数据，包含
稳定模板 ID、名称、适用 kind 与可选实体分类。编辑器和机器入口从该快照说明名称/
范围变化；不能将后来刷新的工程目录或尚未提交的属性输入冒充已核对的旧/新范围。

机器入口可调用 core 的 `preview_template_mutation_with_limits`，提供
`TemplateImpactLimits { max_instances, max_field_values, max_output_bytes }`。
实例预算按真实旧/新适用范围并集行数计算，字段值预算按实际适用侧的叶字段值数计算，
计数使用溢出检查。字节预算覆盖 core 影响 payload 的 JSON（字段变更、实例、诊断、
旧新元数据与完整性标记），不含私有候选 Project 与请求原文字节；机器最终 envelope
仍另行遵守协议总预算。core 在克隆实例属性值或分配完整结果前用借用投影和有界
计量预检，单个长值同样提前计量；字段表只建立一次并借用，不逐对象深克隆模板或
整张属性表。超出任一预算以 `TemplateImpactLimit` 失败，不返回截断却标为完整的
结果，也不修改 Project。旧无预算预览与高级 JSON 路径不因此被悄悄降额。

新机器入口采用明确限额：最多 10,000 个实际适用实例、100,000 个适用侧叶字段值，
core 影响 payload 最多 8 MiB；完整线协议 plan（含摘要）仍须最终流式核验 8 MiB
上限。预算为 0 时，只允许对应零项/零字节结果，不隐式替换为默认上限。

每条字段变更携带 `old_properties`、`new_properties` 两侧的可选已知属性快照：显示
名称、key、字段类型、required、choices、引用目标 kind / entity_type 与 default。
快照不递归包含子字段；子字段有自己的稳定 ID 变更行。新增只有新侧，删除只有旧侧。
字段位置变化与复合属性变化仍保留确切两侧值，不能只显示笼统“约束变化”。这些
快照绑定预览生成时的文档，不从之后改过的界面输入或工程目录重新推断。受限接口
在复制长选项、默认提示或名称前对借用快照计量；快照计入相同影响 payload 预算。
