# 普通外部改稿的受保护续写（工具 0.32）

本规范扩展 [workspace.md](workspace.md) 的普通外改冲突；不替代可恢复保存事务，
不引入同步、Git 合并、自动覆盖或另一份正文。core 是快照、候选、诊断及应用守卫的唯一真源。

## 身份、范围与保护

一次 `ReconciliationSession` 绑定同一 Project root、entry、外部刷新代次、全部受跟踪
源码和已注册 JSON 的当前原始字节、删除状态、保存基线、只读状态，以及完整工作区
文件库存与磁盘字节。公开摘要用于说明陈旧原因，不是签名或写入授权；core 最终逐字节
比较私有捕获证据。缺失使用 `None`，空文件使用 `Some([])`，两者永远不同。

冲突项来自已跟踪且本地相对保存基线有修改、磁盘也不等于保存基线的文件。三方分别为
已保存基线、本地已应用缓冲、捕获时磁盘；不推断共同祖先，不按标题、段落或对象名称
猜测身份。普通未注册 JSON 与附件不成为编辑对象，但纳入磁盘变化守卫且保持原字节。
未载入的新源码、无本地修改文件的外改或注册库存漂移要求先刷新；捕获不暗中刷新工程。

未知清单能力、未知文档格式/必需能力、不能解码的任何一方、不可确认的文件身份、链接、
只读目标与未解决 `.world/.transactions` 均阻断应用并保留快照；不得用选择一侧绕过。
展示 JSON 需可由无重复键解析器确认为对象及受支持格式；此入口不修复未知/raw-byte 文档。
事务恢复继续使用原有恢复/救援流程，普通续写不恢复、删除或清理事务日志。

扫描最多 4096 文件；磁盘与每套缓冲证据各最多 64 MiB，单个输入最多 16 MiB。
超预算失败而非返回可应用的截断计划。源码、JSON 原文与缺失状态完整保留。

## 显式候选与完整预览

`Project::capture_reconciliation()` 只读取证并返回会话；无写入、无基线推进。
调用方针对每个冲突文件传入 `ReconciliationChoice`：保存基线、本地、磁盘或手工 UTF-8
全文，另有明确删除候选。初始没有默认选择，不提供“接受所有”或自动合并。
选择一侧逐字节复制该侧；手工文本逐字节使用用户提交值，不重排 JSON、不丢未知字段。
切换选择可以改变当前候选，但关闭、取消、陈旧与校验失败不清除用户输入。

`Project::preview_reconciliation(session, choices)` 在隔离 Project 上应用全套明确候选，
生成逐文件三方与结果、未解决数、完整工程问题报告及运行指纹前后值。候选集不得含
非冲突路径、重复路径或越界路径。未解决项仍显示原本地材料；有未解决项不能应用。
所有活动源码及已注册创作文档使用现有 core 编译器和工程问题投影验证；包含语法、正式
引用、清单和展示文档诊断，不由 GUI 局部解析代替。坏候选、能力不支持、报告不完整/
截断均不能应用。纯 `.wl` 语法/语义错误完整展示；只有明确勾选
“保留为未完成源码”才允许采纳，结果标为不可运行，不宣称编译通过。已注册文档自身
error 诊断仍硬拒绝；仅由正文错误导致的 `content_incomplete` 依赖覆盖须如实披露，
不能当作文档检查成功或隐藏诊断。应用前仍可编辑候选并重新预览。

清单注册变更必须在完整候选中成立：新增登记项从同一捕获磁盘取得；移除登记不删除
文件、不默默丢弃脏缓冲。无法无歧义保留的注册生命周期变化拒绝，并指向既有正式
文档/清单操作。既有扩展字段与所有未选文件原字节保持不变。

## 应用、磁盘第二次变化与撤销

`Project::apply_reconciliation(plan)` 必须重新捕获并核对完整会话身份，重新生成完整
候选与报告，并逐项对比已审阅计划。反序列化 DTO、公开摘要或修改 `can_apply` 均不构成
授权。重新编译后、提交内存前再检查完整磁盘、事务和目标可写性；第二次外改导致整批
零修改。重复点击同一计划失败，不能重复推进基线。

成功只将候选一次性采纳到内存；冲突目标的保存基线推进到本次实际核验的磁盘原字节，
而非候选或旧基线。未冲突文件基线不变。Project 刷新代次前进，旧计划及更早历史失效。
返回结果包含专用撤销 Project：作者内容是采纳前的本地稿，保存基线仍是刚核验磁盘，
并具有新代次。宿主清空旧撤销/重做后将此快照作为一个撤销步骤；之后用现有
`Project::restore` 撤销/重做，不能恢复旧保存基线或写磁盘。其后真正外改按原规则使
撤销失效；保存本地稿不使同代次撤销失效。

Save 是另一个明确动作，仍经过保存预检与可恢复事务。采纳磁盘侧可能成为干净缓冲；
采纳本地/手工/删除可能仍为待保存稿。采纳、撤销、重做、失败与取消都不写作者文件。
采纳后再次外改仍由普通保存守卫拒绝覆盖；保存失败不撤销已采纳缓冲，不伪称已落盘。

## 编辑器、草稿与浏览器

窗口保留既有 5 工作台风格、17 配色和语义 token。宽屏可并排，窄屏/高缩放使用三方
与候选切换；文件选择、长中文路径、每一方全文及顶部关闭/取消始终可达。Escape
关闭并保留候选；重新打开同一工作区继续原会话，显式“重新捕获”不会默默丢弃手工稿。
初次打开提供明确键盘焦点；关闭后恢复原焦点，不把按键穿透到正文。

未应用 WritingBuffer、源码 IME 及表单输入不是已应用 Project 的一部分。预览可只读
进行，但采纳必须在宿主确认没有此类未提交输入时进行；不自动应用、丢弃或替换。
关闭窗口返回原稿，失败仍保留所有输入；成功刷新派生视图并保留作者来源位置。
浏览器使用同一 core 合同，但只核验用户已导入的 file_access 快照，不声称磁盘监视。
重新导入产生新会话，旧会话不可采纳；下载另循原浏览器保存合同。

## Rust、CLI 与 RPC

Rust 暴露捕获、预览和受守卫的内存应用。机器请求仅描述会话输入、明确候选与已审阅
计划身份；CLI/RPC 不另写合并规则，不绕过完整重验，不隐含 Save。无持久 Project 的
一次性接口通过显式当前稿输入建立隔离预览，可输出候选与诊断；写回需独立显式保存
动作并复用同一磁盘和事务守卫。错误须以 `ok:false` 报告领域失败，协议格式错误才使用
JSON-RPC error。精确命令与请求例随实现记录在用法文档。

## 回归

覆盖非重叠/重叠、删除/修改、缺失/空、Unicode/长行、多文件整批、注册 JSON 扩展字段、
只读、未知能力、坏 UTF-8、未解决事务、伪造/过期计划、预览期间及提交前第二次外改、
取消/重复点击、草稿保护、撤销/重做、保存失败/保存后撤销及重开。无关文件字节必须不变。
实际 UI 验收含 800×600 与 200%：逐一访问全部三方、候选、预览、采纳及关闭。

### 机器入口的精确形状

能力：`authoring.workspace_reconciliation.v1`。RPC 使用现有 `project_id`：

- `reconciliation.capture {project_id}`：只读捕获，缓存 core session，返回 `{ok,session}`
- `reconciliation.preview {project_id,request}`：`request` 为
  `{choices:[{path:"world.wl",choice:{kind:"local"}}],allow_incomplete_source:false}`，
  返回 `{ok,plan,applied:false,saved:false}`；choice.kind 为 baseline/local/disk/manual/delete，
  manual 额外含 `text`。未选择文件不自行补默认侧
- `reconciliation.apply {project_id,plan_digest}`：只接受此会话已预览的完整 core plan，
  返回 `{ok,plan,baseline,applied:true,saved:false}`；重复或过期失败
- 保存继续使用既有 `project.save`，不为续写隐式调用保存

CLI：`wl reconciliation capture|preview|apply|save <目录或入口> --input <JSON文件>`。
preview/apply/save 另需 `--request <JSON文件>`，apply/save 另需 `--plan-digest <预览摘要>`；
`--json` 返回同一 core session/plan。input 是显式提供的作者材料，绝不宣称来自当前编辑器：
`{schema_version:1,files:[{path:"world.wl",baseline:[字节],local:[字节]}]}`。
`null` 是明确缺失，`[]` 是空文件。只允许受跟踪源码及旧/本地清单明确注册JSON，不接管附件。
CLI 每次建立隔离 Project，从实际工作区读取磁盘，复用同一捕获/重验。
apply 只输出真实候选文件字节和 `applied:true,saved:false`，进程退出不持久保存内存。
独立 save 命令仍必须重建并比对已审阅摘要，再明确调用原有可恢复保存。
保存失败返回实际 `applied:true,saved:false` 与错误，不回滚缓冲或删除恢复日志。
合法输入的领域失败为 `ok:false`，CLI退出1；参数/JSON格式错误退出2，RPC为-32602。

后台宿主可先调用 `prepare_reconciliation_with_progress`，取得不能自行构造或反序列化的
`PreparedReconciliation`，再在实际会话上调用 `commit_prepared_reconciliation`。
准备不修改 Project，最后提交仍完整核验当前缓冲、保存基线、刷新代次、磁盘库存/字节、
事务与目标可写性；后台完成不是采纳成功。取消/关闭丢弃待提交结果并保留候选输入。


清单采纳若新增登记了磁盘已存在的文件，专用undo同时保留这些文件的干净原字节缓冲，
即使undo还原的是未登记它们的旧清单。它们不是本地新建，不能因通用restore补墓碑而被
误删；undo/redo/保存后外部文件字节仍保留，正常刷新可解除无本地修改的旧登记跟踪。

### 编码预算与错误

机器适配层的原文预算和 JSON 编码预算分别计算。RPC 在克隆请求 DTO 前对借用参数作
流式编码计数：params 最多32 MiB、整个请求对象最多32 MiB+4096、request id 最多2048个
编码字节；project_id 最多256字节，plan_digest 是16位十六进制。RPC session/plan结果
先对借用的完整payload计数至32 MiB，再构造JSON Value及缓存。完整JSON-RPC响应连同
id、外壳及最后换行上限32 MiB+4096。超限id用null响应，不反射巨大标识。

CLI input/request各在读取时限制32 MiB编码字节；相对路径最多4096字节/128层，候选最多
4096项。CLI完整成功响应（包括最后换行）在动作前编码到32 MiB有界缓冲；原始字节数组
的数字、逗号、转义与外壳全部计入，不能用原文Vec长度代替。输出超限返回
`OUTPUT_LIMIT`，没有采纳或保存，也不返回可误读为完整的截断候选。

RPC和CLI的apply在动作前预检本次完整成功结果；CLI save也先完成同一预检。保存实际
失败才返回`SAVE_FAILED`、`applied:true,saved:false`，保留真实事务状态，绝不回滚或假报
零修改。合法但不可采纳的候选为`RECONCILIATION_REJECTED`；CLI参数/材料格式问题为
`INVALID_PARAMS`与退出2，RPC相应使用-32602。错误详情允许明确标识的有界裁剪，完整候选
和诊断证据不裁剪交付。这些限制约束本方法克隆及输出，不声称改变旧stdio公共读取器的
全局行读取/初次JSON解析行为。
