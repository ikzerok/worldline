# 后台任务的工作区快照契约

本契约用于编辑器的有界后台预览与导出计算，不改变[工作区](workspace.md)的文件边界、完整备份或保存事务。快照与结果不是新的语言真源；所有解释、诊断、结构编辑和发布选择仍由 core 生成。此能力不提高默认语言 1.9 或既有最高语言 1.13。

## 捕获

`Project::snapshot_files` 捕获当前已应用内存缓冲和工作区普通文件。它不刷新磁盘、不编译、不迁移、不保存，也不推进保存基线。`.wl` 和已注册展示文档采用当前缓冲；未注册文件使用工作区原始字节；未解决保存事务仍拒绝捕获一致快照。事务目录与本地检查点历史不进入普通作品文件。

`Project::snapshot_files_limited` 在复制大缓冲或读入文件前检查文件数和累计原始字节预算。逐文件读取受剩余额度限制，目录枚举也有界；不能先构造无界完整副本再报超额。已删除的受跟踪文件不计入活动文件集合，但精确重建所需的墓碑字节仍计入后台传输总额度。

所有相对路径必须由工作区边界模块验证。拒绝绝对路径、父目录逃逸、链接、重复路径、来源与相对路径不一致和注册身份冲突。保留无效 UTF-8 或无效 JSON 展示文档的原字节，不以空文档替代。

## 精确状态

`Project::snapshot_state` 返回 schema 1 的受跟踪文档描述：相对路径、是否展示文档、是否已删除、只读状态，以及删除态重建所需的原始保留字节。描述中的跟踪集合是完整集合，不能由有效活动文件列表反推。未知 schema 和未知必需能力明确拒绝执行，但不删除作者的原输入。

`Project::from_snapshot` 与 `Project::from_snapshot_with_state` 只构建隔离计算用 Project，不调用磁盘恢复、目录创建、自动迁移或保存。后者恢复描述所指的精确跟踪状态与墓碑；缺少字节、冗余描述、重复身份和相互冲突的活动/删除记录均拒绝。

重建后的当前内容基线必须与捕获 Project 的基线相同；该基线包括原始字节、受跟踪集合和删除态。临时 Project 的保存参照仅用于私有计算，不授权在原工作区覆盖文件，也不冒充原会话撤销历史。发布内容不得含墓碑原文。

## 有界传输

后台请求采用 typed JSON 元数据和二进制文件侧通道。JSON 上限 32 MiB；活动文件与墓碑保留字节合计最多 10,000 项、128 MiB。调用方可以收紧限制，不能放宽核心任务自身更低的预算。

墓碑字节不转成 JSON 数字数组；描述通过精确路径映射到独立二进制负载。主线程发送前和计算端接收后都检查数量、字节数、重复路径及描述一致性。元数据声称的长度不替代实际接收长度检查。

## 结果授权边界

后台返回 typed 预览、正规化请求或派生图像/发布包。不得返回可以直接绕过 core 写入的任意候选文件集合。私有 `ScenePlan` 不接受反序列化为可信提交许可。

应用前由调用方检查工作区身份、会话代次、任务 ID、修订与完整内容基线，并由 core 重新验证正规化请求。任务取消、切换工作区、撤销/重做、丢弃输入或较新请求均使旧结果失效。错误、超额、取消、陈旧和畸形结果保持作者稿件零变更。

发布包是派生结果，其最终交付必须重新核对显式选择、profile 与基线。后台计算不触发下载、浏览器打开、磁盘导出或原稿保存。

## 回归要求

- 未保存新增、修改、删除及坏 UTF-8 展示文档可精确重建内容基线
- 只读/未知能力与未注册普通文件不丢失、不隐式接管
- 墓碑负载不泄漏到发布包，活动文件计数不被已删除磁盘文件误占
- 大文件在读取/复制前受限，边界处数量、累计字节和路径错误零修改
- 多次请求、取消、关闭、切换工程和撤销后的过期结果不能应用
