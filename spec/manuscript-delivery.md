# 同范围连续审稿与作者 Markdown 交付

工具 0.32。此能力读取一份书稿的既有文字、状态、POV、分节查询；不新增持久集合，不改变语言版本、运行指纹或公开读者白名单。

## 范围和来源

`ManuscriptDeliveryRequest`（schema_version 1）含 `query: ManuscriptQueryRequest`、可选 `chapter_ids`、可选 `expected_snapshot_key` 与显式 `limits`。查询只保留书稿 ID、文字、状态、POV、分节条件；树折叠、导航页和当前行不缩小结果。`chapter_ids=None` 指完整匹配结果；`Some` 明确指定匹配结果内的稳定章 ID（空数组是空范围），重复、歧义、缺失或不匹配 ID 均拒绝。输出总按 core 书稿前序，不能按输入 ID 顺序、标题或源目标重排。

`ManuscriptDeliverySnapshot` 在一个冻结 Project、按文件唯一的 WritingBuffer 集合与明确编排草稿上建立查询及审稿来源。查询一次完整确定范围，后续分页和逐章审稿不重新编译或读取磁盘。`expected_snapshot_key` 如有必须等于该查询快照的 key。正文草稿基线、原文或同路径身份不能确认时失败；不会挑旧稿或同名对象替代。完整内容基线、观察代次、正文代次、编排和查询选择共同绑定缓存与交付守卫。

查询真正建立时在编译前后采集一致的只读库存/可读性观察，并将该观察绑定快照。明确生成、来源和交付动作使用core的 `verify_manuscript_delivery_observation` 重新检查，不能等下次后台刷新才发现附件删除或失去可读性；idle帧和缓存命中不读盘。该观察不声称附件内容字节未变，附件仍完全不进入审稿材料。WASM使用当前已授权挂载快照的同一file_access观察，不读取或声称监视宿主磁盘。

`ManuscriptDeliveryScope` 给出快照 key、规范化查询、书稿 ID/标题、当前工程稿/含未应用稿的来源标记、匹配章数、选中出现次数、唯一源数、重复源出现次数、完整性和诊断。`writing_inputs` 逐文件列出工作区相对路径、草稿代次与字节数，供作者核对纳入范围，不携带原文全文。每章保留稳定 ID、全书 ordinal、完整分节身份/标题路径、标题、TargetRef 和来源状态。多个章引用同一源时逐次保留并注明重复；同名不同 ID 不合并。

未提交表单、未插入的保留输入、进行中的 IME 不视为已纳入正文。编辑器在生成入口明确列出排除项；组合输入未完成时不得启动/交付。运行模式不适用：此处始终是作者静态全分支资料。

## 连续审稿和预算

逐章使用既有 `ReviewProjection`，保留全部互斥条件分支、选择组、say、动态文字、结构语句、call 与返回边界。条件不求值，call 仅保留未展开标记；不会从另一入口执行，也不会把编排顺序说成实际路线。

`ManuscriptDeliveryJob` 是可分步推进的只读作业。进度包含已处理/总出现次数、累计节点/字节和终止状态；取消清除未完成产物，重复点击不产生第二份有效结果。默认/硬上限：4096 个选中章、100000 个审稿节点、4 MiB 范围身份/路径、16 MiB 审稿投影累计 JSON、8 MiB Markdown；调用方只可降低。4096 是本交付格式的专属预算，不修改其它查询或读者发布的合法章节上限。每章继续遵守 ReviewProjection 的单章节点、深度与源码预算。预算按每个出现次数计，不能通过去重绕过。范围或预算无法确认时返回明确错误，不截断为成功。

完整查询范围中的坏章、缺源、歧义或无法生成审稿的章均保留在报告中，附逐章错误；完整性为 false。连续审稿可以查看已确认章及错误占位，但只有范围和全部选中章完整时才生成可复制/导出的 Markdown。无命中是明确的零章报告和有零章说明的完整材料；不冒称作品无问题。

## Markdown 边界与等价性

`ManuscriptDeliveryReport` 含 scope、逐章审稿/错误、预算使用、complete 和可选的 `markdown`。每个出现的 `review_bytes` 是core实际生成的完整ReviewProjection序列化字节数；重复源逐次计量，错误项为0且明确错误，不能把0解释为零字章节。编辑器据此和真实节点数复用12000节点/4MiB单页显示预算，每页最多8个出现，页分界只按完整读序连续推进；错误项也占位置，没有省略后续章。来源返回恢复实际页分界；同筛选重新生成时优先保留稳定章对应页。Markdown 由 core 从该报告的正式静态审稿语义生成，保留书稿/查询/稳定章与源身份、顺序、重复出现说明及全部分支结构。正文采用安全的 Markdown 文字转义；不把用户文字当 HTML、图片或脚本执行。

材料明确标为“作者私密审稿本 · 静态全分支 · 未执行”。只纳入所选章的审稿字段与必要的结构/来源身份；不附加源文件全文、隐藏 JSON、批注、运行值、未选择附件或调用目标正文。不会改变 ReaderProfile 或复用公开读者导出的授权语义。

编辑器直接预览 `report.markdown` 的完整原文，复制及导出使用同一 UTF-8 字节序列，不经第二次渲染、重新拼装或行尾替换。预览和交付分别显式进行；交付前确认作者私密范围并再次核对完整 Project 观察及全部正文/编排/查询输入。任何变更使旧结果保留为只读过期证据，复制、导出及来源跳转停用；重新生成是显式操作。

原生导出只能选择工作区外的全新 `.md` 文件。先在目标目录写入并同步临时文件，再以不覆盖方式发布完整文件；已存在目标、路径逃逸、失败、取消或过期不留下目标产物，不改工程保存状态。不能声称跨文件或掉电持久原子性。WASM 只请求浏览器下载该相同字节，不声称浏览器已保存到磁盘。

## 来源往返及机器入口

来源按钮复用 ReviewSource 的完整快照和字节范围校验，定位准确的当前 WritingBuffer；返回恢复原查询、导航页、章、正文模式、光标和审稿页/滚动。改变正文后仍保留原范围意图，可重新生成；不能凭标题或相似文段猜测新来源。

正文改写会使旧正文选区锚失效，不能借“返回审稿”恢复它。仅当会话绑定的书稿、完整范围请求与冻结report身份仍相同时，可独立恢复该份旧审稿材料的页/滚动；旧材料继续标为过期，来源及交付保持禁用。新report不能沿用另一份材料的旧滚动授权。

Rust API、`wl manuscript-delivery` 与 `manuscript.delivery` RPC 共用上述请求和报告。CLI 可打印报告，显式 `--output` 才导出新文件；RPC 返回同一 Markdown 字符串，不隐式写文件。业务失败为 `ok:false`，非法 DTO 为参数错误；所有响应声明 applied=false、saved=false。输入最大 4 MiB，完整响应最大32 MiB且不截断。DTO 反序列化不构成导航、交付或写入授权。

## 必须覆盖的回归

完整过滤后分页、深分节、同名不同 ID、重复来源、显式空选择/零命中、坏章/缺源/歧义、中文/emoji/长行、全部分支和未展开调用；分步进度、累计预算、取消、过期及重新生成；原工程、磁盘、撤销零变；预览/复制/文件字节相等；新目标不覆盖及失败清理；来源往返保留查询/页/作者位置，native/WASM 交付措辞真实。
